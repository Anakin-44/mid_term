1. Array

Core Concept

An Array is an ordered, zero-indexed, resizable collection of values. In JS, arrays are special objects, can hold mixed types, and have a dynamic length.

Technical Breakdown

const fruits = ["apple", "banana"];         // array literal
const arr2 = new Array(3);                  // 3 empty slots
const arr3 = Array.from("abc");             // ["a","b","c"]
const arr4 = Array.of(7);                   // [7]

// Access and length
fruits[0];            // "apple"
fruits[fruits.length - 1];   // last element
fruits.at(-1);        // "banana" (ES2022, negative index)

// MUTATING methods (change the original)
fruits.push("mango");      // add end   -> returns new length
fruits.pop();              // remove end -> returns removed item
fruits.unshift("kiwi");    // add start
fruits.shift();            // remove start
fruits.splice(1, 1, "pear");   // at index 1 remove 1, insert "pear"
fruits.sort();             // sorts in place (as STRINGS by default!)
fruits.reverse();

// NON-MUTATING methods (return new array/value)
fruits.slice(0, 2);        // copy portion [start, end)
fruits.concat(["fig"]);
fruits.indexOf("apple");   // -1 if not found
fruits.includes("apple");  // true / false
fruits.join(", ");         // "apple, pear"
[1, [2, [3]]].flat(Infinity);   // [1,2,3]

// Iteration / functional methods
[1,2,3].forEach(x => console.log(x));
[1,2,3].map(x => x * 2);        // [2,4,6]
[1,2,3].filter(x => x > 1);     // [2,3]
[1,2,3].reduce((a, b) => a + b, 0);  // 6
[1,2,3].find(x => x > 1);       // 2 (first match)
[1,2,3].findIndex(x => x > 1);  // 1
[1,2,3].some(x => x > 2);       // true
[1,2,3].every(x => x > 0);      // true

// Spread (copy / merge)
const copy = [...fruits];
const merged = [...[1,2], ...[3,4]];   // [1,2,3,4]
Mutating Non-mutating
push, pop, shift, unshift, splice, sort, reverse, fill slice, concat, map, filter, reduce, join, indexOf, includes, flat 
 index :   0       1        2
 value : "apple" "banana" "mango"
 length = 3   (always highest index + 1)
 push  -> adds at index 3      pop  -> removes index 2
 unshift/shift work at index 0 (re-index all other items: slower)

Real-world example: A shopping cart is an array of product objects; filter removes an item, reduce computes the total.

Exam Trap:
  • [10, 9, 1].sort() gives [1, 10, 9] because default sort compares strings. Use sort((a,b)=>a-b).
  • slice (copy, no mutation) vs splice (mutates).
  • const arr2 = arr1 copies the reference, not the data. Use [...arr1].
  • typeof [] is "object"; use Array.isArray().
  • Setting arr.length = 0 empties the array.

2. Object

Core Concept

An Object is an unordered collection of key–value pairs (properties). Values can be primitives, arrays, functions (called methods) or other objects. Keys are strings or Symbols. 

const student = {
  name: "Asha",
  age: 22,
  skills: ["JS", "Node"],
  address: { city: "Dehradun" },
  greet() { return `Hi, I am ${this.name}`; }   // method shorthand
};

// Access
student.name;              // dot notation
student["age"];            // bracket notation (dynamic keys)
const key = "name"; student[key];

// Add / update / delete
student.email = "a@x.com";
student.age = 23;
delete student.email;

// Checking
"name" in student;                     // true
student.hasOwnProperty("age");         // true (own property only)
Object.hasOwn(student, "age");         // modern version

// Useful static methods
Object.keys(student);      // ["name","age",...]
Object.values(student);
Object.entries(student);   // [["name","Asha"], ...]
Object.assign({}, student, {age: 30}); // shallow merge/copy
Object.freeze(student);    // prevents changes (shallow)

// Spread
const clone  = { ...student };                 // shallow copy
const merged = { ...student, age: 25 };        // later keys override

// Computed property name and shorthand
const field = "score"; const score = 90;
const obj = { [field]: 1, score };    // { score: 90 } ← shorthand wins (later key)

// Iterating
for (const k in student) console.log(k, student[k]);
for (const [k, v] of Object.entries(student)) console.log(k, v);

// Constructor function / class
class Person {
  constructor(name) { this.name = name; }
  hello() { return "Hello " + this.name; }
}
const p = new Person("Ravi");
 student ──► { name : "Asha"
               age  : 22
               skills ─► [ "JS", "Node" ]     (reference)
               address ─► { city: "Dehradun" } (reference)
               greet : function }
 Spread/assign copy only the TOP level (shallow).
 Deep copy: structuredClone(obj)  or  JSON.parse(JSON.stringify(obj))
Feature Array Object
Keys Numeric indices (0,1,2..) Strings / Symbols
Order Guaranteed by index Insertion order for strings (integer-like keys first)
Best for Lists Records / entities
Iterate with for...of for...in / Object.entries
Exam Trap:
  • Spread and Object.assign make shallow copies; nested objects remain shared.
  • Arrow functions as methods do not get the object as this.
  • Accessing a missing property gives undefined; accessing a property of undefined throws TypeError (use ?.).
  • {} === {} is false because objects are compared by reference.
  • Dot notation cannot use dynamic or invalid-identifier keys such as obj["first-name"].

3. Array Destructuring

Core Concept

Destructuring (ES6) unpacks values from arrays into distinct variables using a pattern on the left-hand side. Array destructuring is position-based. 

const [a, b] = [10, 20];           // a=10, b=20
const [x, , z] = [1, 2, 3];        // skip with a comma  → x=1, z=3
const [first, ...rest] = [1, 2, 3, 4];   // rest = [2,3,4]
const [p = 5, q = 8] = [1];        // defaults → p=1, q=8
[a, b] = [b, a];                   // swap without temp variable
const [[m, n], o] = [[1, 2], 3];   // nested

// From function return
function minMax(arr) { return [Math.min(...arr), Math.max(...arr)]; }
const [lo, hi] = minMax([4, 1, 9]);   // lo=1, hi=9

// Any iterable works
const [c1, c2] = "hi";             // "h", "i"

// React's useState uses it:
// const [count, setCount] = useState(0);
 const [ a ,  b , ...rest ] = [ 1 , 2 , 3 , 4 ]
         |     |      |
         1     2    [3,4]
Key Concept: Defaults apply only when the value is undefined, not null.
Exam Trap: The rest element must be last. Destructuring undefined or null throws TypeError. A leading line like [a, b] = [b, a] needs a semicolon on the previous line (ASI hazard).

4. Object Destructuring

Core Concept

Object destructuring extracts properties by name (not position) into variables. 

const user = { id: 1, name: "Asha", address: { city: "Delhi", pin: 110001 }, tags: ["a","b"] };

const { id, name } = user;                    // id=1, name="Asha"
const { name: userName } = user;              // rename → userName
const { age = 18 } = user;                    // default value
const { name: n2 = "NA", role: r = "user" } = user;  // rename + default
const { address: { city } } = user;           // nested → city="Delhi"
const { id: uid, ...others } = user;          // rest → others has remaining props

// In function parameters (very common in React/Express)
function show({ name, age = 0 }) { console.log(name, age); }
show(user);

// Express-style usage
// app.post("/signup", (req, res) => { const { email, password } = req.body; })

// Assigning to existing variables needs parentheses
let a, b;
({ a, b } = { a: 1, b: 2 });

// Dynamic key
const key = "name";
const { [key]: dynamicVal } = user;
Aspect Array Object
Matching By position By property name
Brackets [ ] { }
Rename Not needed (any name) { old: newName }
Skip items Leave a hole [ , x] Just omit the key
Exam Trap: In { name: userName } the left side is the property and the right side is the new variable (opposite of object literal creation intuition). { a, b } = obj; without parentheses is a SyntaxError because { is parsed as a block. In nested destructuring, address itself is not declared as a variable.

6. DOM Manipulation

Core Concept

The Document Object Model (DOM) is a tree-structured, in-memory representation of an HTML page that JavaScript can read and modify. document is the entry point (root). 

 document
   └── html
        ├── head ── title
        └── body
             ├── h1#title
             ├── ul.list
             │     ├── li
             │     └── li
             └── button#btn

Selecting Elements

document.getElementById("title");          // single element
document.getElementsByClassName("item");   // live HTMLCollection
document.getElementsByTagName("li");       // live HTMLCollection
document.querySelector(".list li");        // FIRST match (CSS selector)
document.querySelectorAll(".item");        // static NodeList

Modifying Content, Attributes and Style

const h = document.querySelector("#title");
h.textContent = "New <b>Title</b>";   // plain text (safe)
h.innerHTML   = "New <b>Title</b>";   // parses HTML (XSS risk with user input)
h.setAttribute("data-id", "5");
h.getAttribute("data-id");
h.style.color = "red";                       // inline style (camelCase)
h.classList.add("active");                   // also remove, toggle, contains

Creating / Removing Elements

const li = document.createElement("li");
li.textContent = "Item 3";
document.querySelector("ul").appendChild(li);      // add at end
document.querySelector("ul").prepend(li);          // add at start
li.remove();                                       // delete element

// Efficient bulk insertion
const frag = document.createDocumentFragment();
["a","b","c"].forEach(t => {
  const x = document.createElement("li"); x.textContent = t; frag.appendChild(x);
});
document.querySelector("ul").appendChild(frag);

Event Handling

const btn = document.getElementById("btn");
btn.addEventListener("click", (event) => {
  event.preventDefault();       // stop default action (e.g. form submit)
  console.log(event.target);    // element that was clicked
});

// Event delegation: ONE listener on parent handles all children
document.querySelector("ul").addEventListener("click", (e) => {
  if (e.target.tagName === "LI") e.target.classList.toggle("done");
});
Property Behavior
textContent Plain text, fast, safe
innerText Text as rendered (respects CSS), slower
innerHTML Parses HTML, risk of XSS
Key Concept: Events bubble from the target up to ancestors (capturing goes the opposite way). This enables event delegation.
Exam Trap: getElementsBy* return live collections, while querySelectorAll returns a static NodeList. querySelector returns null if nothing matches, so check before use. Scripts must run after the DOM loads (defer attribute or DOMContentLoaded event). Never put user-supplied text in innerHTML.

7. Error Handling

Core Concept

Error handling lets a program detect, report and recover from runtime errors without crashing, using try...catch...finally and throw. 

try {
  const data = JSON.parse("{bad json}");   // throws SyntaxError
} catch (err) {
  console.error(err.name, err.message);    // SyntaxError ...
} finally {
  console.log("Always runs (cleanup)");
}

// Throwing your own errors
function divide(a, b) {
  if (b === 0) throw new Error("Division by zero");
  return a / b;
}

// Custom error class
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}
try { throw new ValidationError("Email invalid", "email"); }
catch (e) {
  if (e instanceof ValidationError) console.log(e.field);
  else throw e;                 // rethrow unknown errors
}

// Async errors
async function load() {
  try { const r = await fetch("/api"); if (!r.ok) throw new Error(r.status); }
  catch (e) { console.error(e); }
}
Built-in Error Cause
SyntaxError Invalid code or JSON
ReferenceError Using an undeclared variable
TypeError Wrong type operation (e.g., calling undefined())
RangeError Value out of range (e.g., new Array(-1))
URIError, EvalError Bad URI function use / eval issues 
 try { ... }  ──error?──► catch(e) { ... } ──► finally { ... } ──► continue
      │ no error                                   ▲
      └────────────────────────────────────────────┘
 finally ALWAYS runs (even after return/throw)
Exam Trap: try/catch cannot catch errors from callbacks that run later (e.g., inside setTimeout) or an un-awaited Promise rejection. fetch() does not reject on HTTP 404/500, only on network failure. You can throw any value, but throw Error objects to keep stack traces. A return inside finally overrides one in try.

8. Asynchronous JavaScript: Callbacks

Core Concept

Synchronous code runs line by line and blocks; asynchronous code starts a task and continues, handling the result later. A callback is a function passed to another function, to be called when work completes. 

// Synchronous callback
[1,2,3].forEach(n => console.log(n));

// Asynchronous callback
console.log("A");
setTimeout(() => console.log("B (after 1s)"), 1000);
console.log("C");           // Output order: A, C, B

// Node.js error-first callback convention
const fs = require("fs");
fs.readFile("a.txt", "utf8", (err, data) => {
  if (err) return console.error(err);   // 1st arg is always the error
  console.log(data);
});

// Callback hell (pyramid of doom)
getUser(1, (err, user) => {
  getOrders(user.id, (err, orders) => {
    getItems(orders[0], (err, items) => {
      console.log(items);        // deeply nested, hard to read and handle errors
    });
  });
});
 Main thread:  A ─► C ─────────────────► B
                     └─ timer runs in Web API / libuv ─┘ (callback queued)

Problems with callbacks: callback hell, scattered error handling, inversion of control (you trust another function to call your callback correctly and exactly once). Promises were designed to fix these.

Exam Trap: Passing fn() instead of fn calls it immediately. For example, setTimeout(fn(), 1000) is wrong. Callback does not always mean async; forEach callbacks are synchronous. Node's convention is error-first: (err, result).

9. Asynchronous JavaScript: Promises

Core Concept

A Promise is an object representing the eventual completion (or failure) of an async operation and its resulting value. 

                  ┌──► fulfilled (resolve(value)) ──► .then(cb)
   pending ───────┤
                  └──► rejected  (reject(error))  ──► .catch(cb)
   Once settled (fulfilled/rejected) the state NEVER changes.
   .finally(cb) runs in both cases.

// Creating a promise
const wait = (ms) => new Promise((resolve, reject) => {
  if (ms < 0) return reject(new Error("negative"));
  setTimeout(() => resolve(`waited ${ms}ms`), ms);
});

// Consuming + chaining
wait(500)
  .then(msg => { console.log(msg); return 42; })   // return value passes on
  .then(n => console.log(n))                       // 42
  .catch(err => console.error(err.message))        // handles ANY earlier rejection
  .finally(() => console.log("done"));

// Static combinators
Promise.all([p1, p2, p3]);         // all fulfil → array; ANY rejection → reject
Promise.allSettled([p1, p2]);      // waits for all; gives status of each
Promise.race([p1, p2]);            // first to settle (win or fail)
Promise.any([p1, p2]);             // first to FULFIL (AggregateError if all fail)
Promise.resolve(5); Promise.reject(new Error("x"));
Method Resolves when Rejects when
all All fulfil Any rejects (fail-fast)
allSettled All settle (never rejects) Never
race First settles fulfilled First settles rejected
any First fulfils All reject

Analogy: Ordering food with a token. You get a token (promise) now; it later becomes either "order ready" (fulfilled) or "sold out" (rejected).

Key Concept: .then() callbacks are microtasks, so they run before setTimeout callbacks (links back to the Event Loop in Unit I).
Exam Trap: Forgetting to return inside .then breaks the chain (next .then gets undefined). Always end a chain with .catch, otherwise you get an unhandled rejection. The Promise executor runs synchronously; only .then handlers are async. Promise.all is fail-fast.

10. Asynchronous JavaScript: Async / Await

Core Concept

async/await (ES2017) is syntactic sugar over Promises that lets async code look synchronous. An async function always returns a Promise; await pauses that function (not the whole thread) until the Promise settles. 

const delay = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));

async function main() {
  try {
    const a = await delay(1000, "A");   // pause here, thread stays free
    const b = await delay(1000, "B");   // runs after A: total ≈ 2s (sequential)
    console.log(a, b);
  } catch (err) {
    console.error("Failed:", err.message);
  } finally {
    console.log("cleanup");
  }
}
main();

// Parallel execution: start all, then await together (≈ 1s)
async function parallel() {
  const [x, y] = await Promise.all([delay(1000, "X"), delay(1000, "Y")]);
  console.log(x, y);
}

// Async arrow, async in loops
const getAll = async (ids) => {
  for (const id of ids) {            // sequential, one after another
    const res = await fetch(`/api/items/${id}`);
    console.log(await res.json());
  }
};

// Return value of async function is a Promise
main().then(() => console.log("finished"));
 Sequential:  |--A(1s)--|--B(1s)--|           = 2 s
 Parallel  :  |--X(1s)--|
              |--Y(1s)--|                    = 1 s
Aspect Callbacks Promises Async/Await
Readability Poor (nesting) Better (chaining) Best (looks synchronous)
Error handling Manual in every callback .catch() try/catch
Return None Promise Promise
Exam Trap: await is only valid inside an async function (or at top level of ES modules). Using await in a forEach callback does not wait; use for...of or Promise.all(arr.map(...)). Awaiting independent tasks one by one is needlessly slow. Without try/catch, a rejected awaited Promise throws and rejects the async function's Promise.

11. Introduction to API

Core Concept

An API (Application Programming Interface) is a contract that lets one software component talk to another. A Web API / REST API exposes resources over HTTP, usually exchanging JSON. 

 ┌────────┐  HTTP Request (method, URL, headers, body)  ┌────────┐   ┌──────────┐
 │ Client │ ─────────────────────────────────────────► │ Server │──►│ Database │
 │ (React)│ ◄───────────────────────────────────────── │(Express)│◄──│ (MongoDB)│
 └────────┘  HTTP Response (status code, headers, JSON) └────────┘   └──────────┘
HTTP Method CRUD Example
GET Read GET /users, GET /users/5
POST Create POST /users (body = new user)
PUT / PATCH Update (replace / partial) PUT /users/5
DELETE Delete DELETE /users/5
Status Code Meaning
200 OK / 201 Created / 204 No Content Success
301 / 304 Redirect / Not Modified
400 Bad Request / 401 Unauthorized / 403 Forbidden / 404 Not Found Client errors
500 Internal Server Error / 503 Service Unavailable Server errors

REST principles: client–server, stateless, uniform interface (resource URLs like /api/users), cacheable, layered. Example endpoint: https://jsonplaceholder.typicode.com/posts/1 returns a JSON post.

Key Concept: Request = method + URL + headers + (body). Response = status + headers + body. REST is stateless: every request carries all information needed.
Exam Trap: 401 = not authenticated (who are you?), 403 = authenticated but not allowed. PUT replaces the whole resource; PATCH changes part of it. GET requests have no body and must not change data. An API is the interface; REST is just one architectural style (others: SOAP, GraphQL).

12. Fetch API

Core Concept

fetch() is the built-in, Promise-based browser API (also built into Node 18+) for making HTTP requests. It returns a Promise that resolves to a Response object. 

// GET
async function getPosts() {
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/posts");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);   // MUST check manually
    const data = await res.json();                        // 2nd promise: parse body
    console.log(data[0]);
  } catch (err) {
    console.error("Request failed:", err.message);
  }
}

// POST with JSON body
async function createPost() {
  const res = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: "Hello", body: "World", userId: 1 })
  });
  return res.json();
}

// PUT / DELETE
fetch("/api/posts/1", { method: "PUT", headers: {"Content-Type":"application/json"}, body: JSON.stringify({title:"New"}) });
fetch("/api/posts/1", { method: "DELETE" });

// Promise-chain style
fetch("/api/data")
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err));
Response Property / Method Purpose
res.ok true if status is 200–299
res.status / res.statusText Numeric code / text
res.json(), res.text(), res.blob() Read body (each returns a Promise, can be read once)
res.headers Response headers
Exam Trap: fetch does not reject on 404/500; it rejects only on network failure, so always check res.ok. You must call res.json() (and await it) to get the data. For POST you must JSON.stringify the body and set the Content-Type header. The body stream can be consumed only once. There is no built-in timeout (use AbortController).

13. AXIOS

Core Concept

Axios is a popular third-party, Promise-based HTTP client for browsers and Node.js. Install with npm install axios. 

import axios from "axios";

// GET: data is already parsed JSON in res.data
async function getUsers() {
  try {
    const res = await axios.get("https://jsonplaceholder.typicode.com/users");
    console.log(res.status, res.data);
  } catch (err) {
    if (err.response) console.error("Server error:", err.response.status);   // 4xx/5xx
    else if (err.request) console.error("No response (network)");
    else console.error(err.message);
  }
}

// POST: object auto-stringified, Content-Type auto-set
axios.post("/api/users", { name: "Asha" });
axios.put("/api/users/1", { name: "Ravi" });
axios.delete("/api/users/1");

// Query params and headers
axios.get("/api/search", {
  params: { q: "node", page: 2 },                   // → /api/search?q=node&page=2
  headers: { Authorization: "Bearer TOKEN" },
  timeout: 5000
});

// Reusable instance + interceptors
const api = axios.create({ baseURL: "https://api.example.com", timeout: 5000 });
api.interceptors.request.use(cfg => { cfg.headers.Authorization = "Bearer T"; return cfg; });
api.interceptors.response.use(r => r, err => Promise.reject(err));

// Parallel requests
const [a, b] = await Promise.all([axios.get("/a"), axios.get("/b")]);
Feature Fetch Axios
Installation Built-in npm install axios
JSON parsing Manual res.json() Automatic (res.data)
Request body Manual JSON.stringify + header Automatic for objects
HTTP error (404/500) Does NOT reject Rejects automatically
Timeout Via AbortController Built-in timeout option
Interceptors No Yes
Cancel request AbortController AbortController (older: CancelToken)
Response data location Result of res.json() res.data
Key Concept: The Axios response object contains data, status, statusText, headers, config, request. The actual payload is always in res.data.
Exam Trap: Axios rejects for non-2xx status (opposite of fetch). Use res.data, not res.json(). Axios is an external library (not part of JavaScript itself). In the error object, err.response exists only if the server replied.

14. JSON: Parse and Stringify

Core Concept

JSON (JavaScript Object Notation) is a lightweight, language-independent text format for data exchange. It is a string, not a JS object.

Rules of JSON syntax

  • Keys must be in double quotes; strings use double quotes only.
  • Allowed values: string, number, boolean, null, object, array.
  • Not allowed: undefined, functions, comments, trailing commas, single quotes, NaN/Infinity, Date objects (they become strings). 
const jsonText = '{"name":"Asha","age":22,"skills":["JS","Node"],"active":true}';

// JSON.parse: string → JS value
const obj = JSON.parse(jsonText);
obj.name;                       // "Asha"

// JSON.stringify: JS value → string
const text = JSON.stringify(obj);                 // compact
JSON.stringify(obj, null, 2);                     // pretty print (2 spaces)
JSON.stringify(obj, ["name"]);                    // only selected keys → {"name":"Asha"}
JSON.stringify(obj, (k, v) => k === "age" ? undefined : v);  // replacer function

// Reviver in parse (e.g. restore dates)
JSON.parse('{"d":"2024-01-01"}', (k, v) => k === "d" ? new Date(v) : v);

// Invalid JSON throws SyntaxError
try { JSON.parse("{'a':1}"); } catch (e) { console.log(e.name); }   // SyntaxError

// What gets lost in stringify
JSON.stringify({ a: undefined, b: () => 1, c: NaN, d: new Date(0) });
// → {"c":null,"d":"1970-01-01T00:00:00.000Z"}  (a and b dropped, NaN → null)

// Deep clone trick (loses functions/undefined/Dates)
const deep = JSON.parse(JSON.stringify(obj));

// Persisting to localStorage (stores strings only)
localStorage.setItem("user", JSON.stringify(obj));
const back = JSON.parse(localStorage.getItem("user"));

Exam Trap: JSON.parse of a non-string or malformed string throws SyntaxError, so wrap it in try/catch. JSON.parse(undefined) also fails. Stringify silently drops functions and undefined properties. Circular references make stringify throw TypeError. JSON.parse(JSON.stringify(x)) is a lossy deep copy; prefer structuredClone. Memorize: parse = string → object, stringify = object → string.
