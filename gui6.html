1. Data Controls (WinForms)

Data controls display, edit, insert and delete data coming from a database or other data source.

Control Role
DataGridView Shows table data in rows/columns; the most common data control
TextBox, ComboBox, Label Show single-record fields
BindingNavigator Navigation buttons (Next / Previous / Add / Delete)
ListBox Lists items (e.g. student names)
Why used: less manual code to display records, built-in data binding, faster UI plus database integration.

2. DataSource and Data Binding

A DataSource is anything that supplies data to controls: a database table (SQL Server, MySQL), a DataTable/DataSet, a List<Student>/array, or XML/JSON (via a DataTable). Data binding connects a control to a data source. 

dataGridView1.DataSource = dt;                            // whole table
textBox1.DataBindings.Add("Text", dt, "Name");            // one column into a TextBox

3. DataSet (ADO.NET)

A DataSet is an in-memory database: an offline container holding multiple tables and relationships without staying connected. 

 DataSet
  |-- DataTable (Students)
  |     |-- DataColumn (Id, Name, Course, Marks)
  |     `-- DataRow    (one record each)
  |-- DataTable (Courses)
  |-- DataRelation  (links Students.Course -> Courses)
  `-- Constraints   (primary key / foreign key rules)

4. DataGridView: Displaying Records

Fetch data into a DataTable using a SqlDataAdapter, then bind it to the grid's DataSource. 

using System.Data;
using System.Data.SqlClient;

private void Form1_Load(object sender, EventArgs e)
{
    string cs = "Data Source=.;Initial Catalog=CollegeDB;Integrated Security=True";
    using (SqlConnection con = new SqlConnection(cs))
    {
        SqlDataAdapter da = new SqlDataAdapter("SELECT Id, Name, Course, Marks FROM Students", con);
        DataTable dt = new DataTable();
        da.Fill(dt);

        dataGridView1.DataSource = dt;     // one line binds the whole table
        dataGridView1.ReadOnly = true;
        dataGridView1.AutoSizeColumnsMode = DataGridViewAutoSizeColumnsMode.Fill;
    }
}
Key Concept: The grid automatically creates one column per DataTable column and one row per DataRow. No manual loop needed.
Exam Trap: da.Fill() opens and closes the connection automatically if it was closed.

5. ADO.NET: Connected and Disconnected Architecture

ADO.NET is Microsoft's data-access technology in .NET for connecting to databases (SQL Server, MySQL), running queries and managing data.

5.1 Connected architecture (live connection)

The app stays connected while reading, inserting, updating or deleting.

  • SqlConnection: opens a connection to the database.
  • SqlCommand: executes a SQL query or stored procedure.
  • SqlDataReader: forward-only, read-only, very fast reads.
 App calls SqlConnection.Open()
        v
 SqlCommand executes the SQL query
        v
 SqlDataReader reads rows (forward-only, read-only)
        v
 Connection stays OPEN the whole time
        v
 con.Close()

using (SqlConnection con = new SqlConnection(cs))
{
    con.Open();
    SqlCommand cmd = new SqlCommand("SELECT Id, Name FROM Students", con);
    SqlDataReader dr = cmd.ExecuteReader();
    while (dr.Read())
        Console.WriteLine($"{dr["Id"]} {dr["Name"]}");
    con.Close();
}
  • Advantages: fast reading, low memory (no local copy), good for real-time operations.
  • Disadvantages: connection stays open (more server load), no offline work, poor for many simultaneous users.

5.2 Disconnected architecture (offline data)

Data is fetched once into memory (DataSet/DataTable); the connection closes quickly and the app works on the local copy.

  • SqlDataAdapter: bridge between the database and the DataSet.
  • DataSet / DataTable: in-memory storage.
  • SqlCommandBuilder: (optional) auto-generates insert/update/delete commands. 
 App opens connection
        v
 SqlDataAdapter.Fill(DataSet) copies data into memory
        v
 Connection CLOSES immediately
        v
 App works OFFLINE on DataSet / DataTable
        v
 (optional) Adapter.Update() sends changes back to DB

using (SqlConnection con = new SqlConnection(cs))
{
    SqlDataAdapter da = new SqlDataAdapter("SELECT Id, Name FROM Students", con);
    DataTable dt = new DataTable();
    da.Fill(dt);                           // connection opens/closes automatically

    foreach (DataRow row in dt.Rows)
        Console.WriteLine($"{row["Id"]} {row["Name"]}");
}
  • Advantages: connection open briefly (scalable), offline use, suits multi-user apps.
  • Disadvantages: more memory, data may become outdated, conflict handling needed.
Feature Connected Disconnected
Connection Open continuously Opens briefly, then closes
Main object SqlDataReader DataSet / DataTable
Speed Very fast for reading Slightly slower
Memory Low Higher
Offline use No Yes
Best for Real-time, small read tasks Large apps, multi-user, caching, grid binding
Exam Trap: SqlDataReader is forward-only and read-only; you cannot go back or edit through it. For editing and navigating freely use DataSet/DataTable.

6. CRUD Operations

CRUD = Create, Read, Update, Delete. Read was covered above; the others use SqlCommand with parameterized queries to prevent SQL injection. 

        CREATE (INSERT)
             |
 DELETE ---- Database ---- READ (SELECT)
 (DELETE)    Table
             |
        UPDATE (UPDATE)

6.1 Insert (Create)

private void btnAdd_Click(object sender, EventArgs e)
{
    string cs = "Data Source=.;Initial Catalog=CollegeDB;Integrated Security=True";
    using (SqlConnection con = new SqlConnection(cs))
    {
        string query = "INSERT INTO Students (Name, Course, Marks) VALUES (@Name, @Course, @Marks)";
        SqlCommand cmd = new SqlCommand(query, con);
        cmd.Parameters.AddWithValue("@Name", textBoxName.Text.Trim());
        cmd.Parameters.AddWithValue("@Course", textBoxCourse.Text.Trim());
        cmd.Parameters.AddWithValue("@Marks", Convert.ToInt32(textBoxMarks.Text));

        con.Open();
        int rows = cmd.ExecuteNonQuery();
        con.Close();
        MessageBox.Show(rows > 0 ? "Record inserted successfully." : "Insert failed.");
    }
}

6.2 Update

string query = "UPDATE Students SET Name=@Name, Course=@Course, Marks=@Marks WHERE Id=@Id";
SqlCommand cmd = new SqlCommand(query, con);
cmd.Parameters.AddWithValue("@Name", textBoxName.Text.Trim());
cmd.Parameters.AddWithValue("@Course", textBoxCourse.Text.Trim());
cmd.Parameters.AddWithValue("@Marks", Convert.ToInt32(textBoxMarks.Text));
cmd.Parameters.AddWithValue("@Id", Convert.ToInt32(textBoxId.Text));

con.Open();
int rows = cmd.ExecuteNonQuery();
con.Close();
MessageBox.Show(rows > 0 ? "Record updated successfully." : "No matching record found.");

6.3 Delete

string query = "DELETE FROM Students WHERE Id=@Id";
SqlCommand cmd = new SqlCommand(query, con);
cmd.Parameters.AddWithValue("@Id", Convert.ToInt32(textBoxId.Text));

con.Open();
int rows = cmd.ExecuteNonQuery();
con.Close();
MessageBox.Show(rows > 0 ? "Record deleted successfully." : "No matching record found.");
Method Use for Returns
ExecuteNonQuery() INSERT / UPDATE / DELETE Number of affected rows
ExecuteReader() SELECT with many rows SqlDataReader
ExecuteScalar() Single value (e.g. COUNT(*)) First column of first row (object)
Exam Trap: Never build SQL by joining strings ("... WHERE Name='" + text + "'"). It allows SQL injection; always use @parameters. A missing WHERE in UPDATE/DELETE affects every row.

7. Login Form Using a Database

Check the entered username and password against a Users table (columns Username, Password). 

private void btnLogin_Click(object sender, EventArgs e)
{
    string cs = "Data Source=.;Initial Catalog=CollegeDB;Integrated Security=True";
    using (SqlConnection con = new SqlConnection(cs))
    {
        string query = "SELECT COUNT(*) FROM Users WHERE Username=@Username AND Password=@Password";
        SqlCommand cmd = new SqlCommand(query, con);
        cmd.Parameters.AddWithValue("@Username", textBoxUser.Text.Trim());
        cmd.Parameters.AddWithValue("@Password", textBoxPass.Text.Trim());

        con.Open();
        int count = (int)cmd.ExecuteScalar();      // single value
        con.Close();

        if (count > 0)
        {
            MessageBox.Show("Login successful!");
            // open the main form here
        }
        else MessageBox.Show("Invalid username or password.");
    }
}
  • ExecuteScalar() returns just the first column of the first row, so it is more efficient than ExecuteReader() for a count check.
  • Set textBoxPass.UseSystemPasswordChar = true to hide typing.
Exam Trap (security): Real applications must store hashed, salted passwords, never plain text. The example is simplified for teaching.

8. Creating a Setup / Installer

Package a finished WinForms app into an installer so users can install it without Visual Studio. In modern Visual Studio this uses the Microsoft Visual Studio Installer Projects extension (the classic "Setup Wizard").

  1. Install the Microsoft Visual Studio Installer Projects extension (Extensions → Manage Extensions) and restart.
  2. Add a new project: File → New → Project → Setup Wizard / Setup Project.
  3. Follow the wizard: "Create a setup for a Windows application", then add the Primary Output of your project.
  4. Add extra files (database file, readme, icons) in the File System Editor.
  5. Set properties: Manufacturer, ProductName, Version; add Start Menu / Desktop shortcut.
  6. Build the setup project (Build → Build Setup1) to produce a .msi and setup.exe.
  7. Distribute them; running installs the app, creates shortcuts and registers it in "Add or Remove Programs".
Key Concept: Output = .msi (Windows Installer package) plus setup.exe (bootstrapper). Users follow the Next → Next → Install → Finish flow.

9. Why using Blocks Matter

// RISKY: if ExecuteNonQuery() throws, con.Close() is never reached
SqlConnection con = new SqlConnection(cs);
con.Open();
cmd.ExecuteNonQuery();
con.Close();                           // leak if the line above threw

// SAFE: using guarantees Dispose() (and Close()) even on exceptions
using (SqlConnection con2 = new SqlConnection(cs))
{
    con2.Open();
    cmd.ExecuteNonQuery();
}

using is shorthand for try/finally: the compiler calls Dispose() inside finally. Leaked connections exhaust the pool and the server's connection limit.

10. Solved Problems

Problem 1: Trace SqlDataReader.Read()

Call to dr.Read() Returns dr["Id"], dr["Name"] now point to
1st true Row 1 (1, "Amit")
2nd true Row 2 (2, "Sita")
3rd true Row 3 (3, "Ravi")
4th false No more rows; the while loop exits

Each Read() advances a cursor by one row; only one row is in memory at a time, and you can never move back.

Problem 2: Duplicate-key insert handled safely

try
{
    con.Open();
    cmd.ExecuteNonQuery();
    MessageBox.Show("Record inserted successfully.");
}
catch (SqlException ex) when (ex.Number == 2627 || ex.Number == 2601)
{
    // 2627 / 2601 = SQL Server UNIQUE / PRIMARY KEY violation
    MessageBox.Show("A student with this email already exists.");
}
catch (SqlException ex)
{
    MessageBox.Show("Database error: " + ex.Message);
}
  • First run: email is new; insert succeeds.
  • Second run (same email): the UNIQUE constraint makes SQL Server throw SqlException with Number 2627.
  • The exception filter (when) gives a friendly, specific message; the general catch handles other DB errors.
