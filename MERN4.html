1. Express JS

Core Concept

Express.js is a minimal, unopinionated, fast web application framework for Node.js (the "E" in MERN). It sits on top of Node's core http module and adds routing, middleware and helper methods for building web apps and REST APIs. It is open-source, created by TJ Holowaychuk and now maintained under the OpenJS Foundation.

Technical Breakdown

  • Framework vs library: Express is a framework for the server layer; it defines how requests flow (routing + middleware), while you choose the database, templating and structure.
  • Role in MERN: React sends HTTP requests, Express receives them, runs logic, talks to MongoDB (via Mongoose) and returns JSON.
  • Unopinionated: no enforced folder structure or ORM.
 React (browser) ──HTTP──► Express (routes + middleware) ──► Mongoose ──► MongoDB
        ▲                           │
        └────────── JSON ◄──────────┘

Real-world example: A login endpoint POST /api/login validates input in middleware, checks the user in MongoDB, and returns a JWT as JSON.

Exam Trap: Express is not a language or a runtime. It is a package installed through NPM that runs on Node.js. Do not confuse it with React (frontend) or Node.js (runtime).

2. Introduction to Express JS

Key Features

Feature Explanation
Routing Map HTTP method + URL to a handler function
Middleware Functions that run in a pipeline before the final response
Template engines Render HTML dynamically (EJS, Pug, Handlebars)
Static file serving express.static() serves CSS, JS, images
Error handling Dedicated error-handling middleware
Helper methods res.json(), res.redirect(), req.params etc.
Huge ecosystem cors, morgan, helmet, passport, multer, etc.

Raw Node.js vs Express

// ---- Raw Node http: manual URL/method checks, manual headers, manual body parsing
const http = require("http");
http.createServer((req, res) => {
  if (req.method === "GET" && req.url === "/users") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify([{ id: 1 }]));
  } else {
    res.writeHead(404); res.end("Not found");
  }
}).listen(3000);

// ---- Express: same thing, much cleaner
const express = require("express");
const app = express();
app.get("/users", (req, res) => res.json([{ id: 1 }]));
app.listen(3000);
 Request ─► Middleware 1 ─► Middleware 2 ─► Route Handler ─► Response
              (logger)       (auth/parse)     (business logic)
 Express app = a pipeline of functions (the "middleware stack")
Key Concept: Everything in Express is either middleware or a route handler. A route handler is simply the last middleware in the chain.
Exam Trap: Express does not replace Node's http; it wraps it. express() returns an app function that can be passed to http.createServer(app).

4. Creating Server using Express JS

Step-by-step

  1. Import Express.
  2. Create an application object with express().
  3. Register middleware and routes.
  4. Start listening on a port with app.listen().
// index.js  (CommonJS)
const express = require("express");
const app = express();                 // 1. create app
const PORT = process.env.PORT || 3000;

app.use(express.json());               // 2. middleware: parse JSON bodies

app.get("/", (req, res) => {           // 3. route
  res.send("Hello from Express!");
});

app.get("/api/status", (req, res) => {
  res.json({ ok: true, time: new Date() });
});

app.use((req, res) => {                // 4. fallback: 404 (runs if nothing matched)
  res.status(404).json({ error: "Route not found" });
});

app.listen(PORT, () => {               // 5. start server
  console.log(`Server running at http://localhost:${PORT}`);
});

// Run:  node index.js    or    npm run dev
// Test: open http://localhost:3000 or use Postman / curl
// ES Module version (package.json: "type": "module")
import express from "express";
const app = express();
app.get("/", (req, res) => res.send("ESM server"));
app.listen(3000);
 Browser: GET /api/status
      │
      ▼
 app.use(express.json())  ──► app.get("/api/status") ──► res.json({...})
      │ (no match?) ──────► 404 fallback middleware
Exam Trap: Order matters: the 404 fallback must come after all routes. A request that never gets a response (res.send/json/end not called and next() not called) hangs forever. Port already in use gives EADDRINUSE.

5. Web Browser Building (Serving Pages to the Browser)

The syllabus phrase "Web Browser Building" is interpreted here as making the Express server deliver web pages and assets to a browser: static files, HTML files, dynamic template-rendered views and JSON to a front-end.

Technique 1: Static files with express.static

const path = require("path");
app.use(express.static(path.join(__dirname, "public")));
// public/index.html  → http://localhost:3000/
// public/style.css   → http://localhost:3000/style.css
// public/app.js      → http://localhost:3000/app.js

// With a URL prefix (virtual path)
app.use("/assets", express.static(path.join(__dirname, "public")));
// public/logo.png → http://localhost:3000/assets/logo.png

Technique 2: Sending an HTML file

app.get("/about", (req, res) => {
  res.sendFile(path.join(__dirname, "views", "about.html"));   // absolute path required
});

Technique 3: Template engine (server-side rendering)

// npm install ejs
app.set("view engine", "ejs");                    // default engine
app.set("views", path.join(__dirname, "views"));  // folder of templates

app.get("/profile", (req, res) => {
  res.render("profile", { name: "Asha", skills: ["JS", "Node"] });
});

// views/profile.ejs
// <h1>Hello <%= name %></h1>
// <ul><% skills.forEach(s => { %><li><%= s %></li><% }) %></ul>

Technique 4: Serve a built React app (MERN deployment)

// After "npm run build" in React, the folder is "dist" (Vite) or "build" (CRA)
app.use(express.static(path.join(__dirname, "client", "dist")));

app.use("/api", apiRouter);                       // API routes first

// SPA fallback: send index.html for any other path so React Router works
app.get("/{*splat}", (req, res) => {              // Express 5 syntax (Express 4: app.get("*", ...))
  res.sendFile(path.join(__dirname, "client", "dist", "index.html"));
});
Approach Rendered where Use case
Static files Browser HTML/CSS/JS, images
Template engine (EJS/Pug) Server Server-rendered pages
JSON API + React Browser (React) MERN apps (most common)
Exam Trap: res.sendFile needs an absolute path (use path.join(__dirname, ...)). Relative paths in express.static depend on the folder you launched node from. The static folder name itself is not part of the URL. Place the SPA catch-all route after API routes or it will swallow them.

6. Express Router

Core Concept

express.Router() creates a modular, mountable, mini-application that holds its own routes and middleware. It keeps big apps organized by splitting routes into files by resource (users, products, orders). 

// routes/users.js
const express = require("express");
const router = express.Router();

router.use((req, res, next) => {            // middleware only for this router
  console.log("Users router:", req.method, req.url);
  next();
});

router.get("/", (req, res) => res.json([{ id: 1, name: "Asha" }]));      // GET /api/users
router.get("/:id", (req, res) => res.json({ id: req.params.id }));       // GET /api/users/5
router.post("/", (req, res) => res.status(201).json(req.body));          // POST /api/users

// Chaining multiple methods on the same path
router.route("/:id/profile")
  .get((req, res) => res.send("get profile"))
  .put((req, res) => res.send("update profile"))
  .delete((req, res) => res.send("delete profile"));

module.exports = router;

// index.js
const userRoutes = require("./routes/users");
const productRoutes = require("./routes/products");
app.use("/api/users", userRoutes);         // mount with a prefix
app.use("/api/products", productRoutes);
 index.js (app)
   ├── app.use("/api/users",    usersRouter)    ── "/" , "/:id"
   └── app.use("/api/products", productsRouter) ── "/" , "/:id"

 Final URL = mount prefix + router path
 "/api/users" + "/:id"  =  /api/users/:id

Recommended Project Structure (MVC-style)

backend/
├── index.js / server.js
├── routes/       userRoutes.js
├── controllers/  userController.js   (handler logic)
├── models/       User.js             (Mongoose schemas)
├── middleware/   auth.js
└── config/       db.js

// controllers/userController.js
exports.getUsers = async (req, res) => { res.json([]); };
// routes/userRoutes.js
router.get("/", require("../controllers/userController").getUsers);
Exam Trap: Inside a router, paths are relative to the mount point; write router.get("/"), not router.get("/api/users"). Forgetting module.exports = router causes "Router.use() requires a middleware function". A router is middleware, so it is mounted with app.use(), not app.get(). To access parent params, create it with express.Router({ mergeParams: true }).

7. Express Listen Method

Core Concept

app.listen() binds the app to a host and port and starts accepting connections. Internally it is a convenience wrapper: http.createServer(app).listen(...). It returns the underlying http.Server object.

Syntax Variants

app.listen(3000);                                      // port only
app.listen(3000, () => console.log("Started"));        // port + callback
app.listen(3000, "127.0.0.1", () => {});               // port + host
app.listen(process.env.PORT || 3000);                  // cloud hosts assign PORT

// Handle errors such as port in use (Express 5 passes the error to the callback)
const server = app.listen(3000, (err) => {
  if (err) return console.error("Failed to start:", err);
  console.log("Listening on", server.address().port);
});

// Equivalent manual form
const http = require("http");
http.createServer(app).listen(3000);

// HTTPS version
const https = require("https"), fs = require("fs");
https.createServer({ key: fs.readFileSync("key.pem"), cert: fs.readFileSync("cert.pem") }, app).listen(443);

// Graceful shutdown
process.on("SIGTERM", () => {
  server.close(() => { console.log("Server closed"); process.exit(0); });
});
Argument Meaning
port Number to listen on (0 = random free port)
host Interface; default all interfaces. "localhost" restricts to local machine
callback Runs once the server is ready
Exam Trap: Registering routes after listen() still works (routes are checked at request time), but it is poor style. Hard-coding a port breaks on Heroku/Render/AWS, so read process.env.PORT. EADDRINUSE means the port is taken. The callback runs on startup, not on each request. Common ports: 3000/5000/8080 (never use 80/443 without privileges).

8. Request Matching

Core Concept

When a request arrives, Express walks through the registered middleware and routes in the exact order they were defined and runs those whose HTTP method and path pattern match. A response ends the chain; next() continues it.

Matching Rules

Registration Matches
app.get("/users", h) Only method GET and path exactly /users (trailing slash and case are ignored by default)
app.use("/api", h) Any method; path starts with /api (e.g. /api, /api/x/y); strips prefix from req.url
app.all("/secret", h) Any HTTP method on /secret
app.get("/users/:id", h) One segment after /users/
app.get(["/a", "/b"], h) Array of paths
app.get(/^\/ab/, h) Regular expression
app.get("/files/{*path}", h) Wildcard (Express 5; Express 4 used /files/*)
app.get("/ab{c}d", h) Optional part (Express 5; Express 4 used /ab?cd) 
app.use((req, res, next) => {                 // runs for EVERY request first
  console.log("1. logger", req.method, req.url);
  next();                                      // pass control to the next match
});

app.get("/users/new", (req, res) => res.send("form"));       // specific FIRST
app.get("/users/:id", (req, res) => res.send("user " + req.params.id));

// Multiple handlers on one route
app.get("/dashboard", checkAuth, loadData, (req, res) => res.send("ok"));

// "next('route')" skips remaining handlers of THIS route only
// "next(err)" jumps straight to the error-handling middleware

app.use((req, res) => res.status(404).send("Not found"));    // nothing matched
app.use((err, req, res, next) => {                           // 4 args = error handler
  console.error(err);
  res.status(500).json({ error: "Server error" });
});
 GET /users/new
   │
   ├─ 1. app.use(logger)            match → next()
   ├─ 2. app.get("/users/new")      MATCH → res.send("form")  ■ STOP
   └─ 3. app.get("/users/:id")      never reached
 If the order of 2 and 3 were swapped, ":id" would capture "new".
Key Concept: First match wins (once a response is sent). Define specific routes before generic/parameterized ones, and the 404 handler last.
Exam Trap: app.use matches by prefix and any method; app.get matches the full path and only GET. A wrong order (/users/:id before /users/new) causes the wrong handler to run. Calling both next() and res.send(), or sending twice, gives "Cannot set headers after they are sent to the client". Express 5 removed the old * and ? path syntax; use {*name} and {...}.

9. Route Parameter

Core Concept

A route parameter is a named dynamic segment of the URL path written with a colon (:name). Its captured value is stored in req.params as a string. It is used to identify a specific resource (/users/42). 

// Single parameter
app.get("/users/:id", (req, res) => {
  res.json({ id: req.params.id });          // GET /users/42  → { id: "42" }
});

// Multiple parameters
app.get("/users/:userId/posts/:postId", (req, res) => {
  const { userId, postId } = req.params;    // /users/5/posts/9
  res.send(`User ${userId}, Post ${postId}`);
});

// Type conversion (params are ALWAYS strings)
app.get("/items/:id", (req, res) => {
  const id = Number(req.params.id);
  if (Number.isNaN(id)) return res.status(400).json({ error: "id must be a number" });
  res.json({ id });
});

// Regex constraint (Express 4 style: /:id(\\d+)); Express 5 → validate manually or use router.param
// Optional parameter (Express 5): /:lang{/:page}
app.get("/blog{/:page}", (req, res) => res.send(req.params.page ?? "home"));

// router.param: run logic whenever :id appears (e.g., load document once)
router.param("id", (req, res, next, id) => {
  if (!/^[0-9a-fA-F]{24}$/.test(id)) return res.status(400).send("Invalid ObjectId");
  next();
});

// Typical MongoDB usage
app.get("/api/products/:id", async (req, res) => {
  const product = await Product.findById(req.params.id);
  if (!product) return res.status(404).json({ error: "Not found" });
  res.json(product);
});

Route Params vs Query String vs Body

Source Example URL / request Access Typical use
Route parameter /users/42 req.params.id Identify one resource
Query string /users?role=admin&page=2 req.query.role Filter, sort, paginate, search
Request body POST with JSON req.body Create/update data
Header Authorization: Bearer ... req.headers / req.get() Auth, content type 
 Route:  /users/:userId/posts/:postId
 URL  :  /users/5/posts/9?sort=desc
                 │        │     └─► req.query  = { sort: "desc" }
                 │        └───────► req.params = { userId:"5", postId:"9" }
 (query string is NOT part of the route pattern)
Exam Trap: req.params.id is a string ("42"), so req.params.id === 42 is false. Do not put the query string in the route definition. Static routes like /users/new must be declared before /users/:id. Route params are case-preserved but their names are case-sensitive.

10. Handler Function

Core Concept

A handler function (route handler / callback) is the function Express runs when a request matches a route. Its standard signature is (req, res, next). It reads the request, performs logic, and must either send a response or call next(). 

// Basic
app.get("/hello", (req, res) => res.send("Hello"));

// Named function (reusable / testable)
function getHello(req, res) { res.send("Hello"); }
app.get("/hello2", getHello);

// Multiple handlers (a chain)
const log  = (req, res, next) => { console.log("log"); next(); };
const auth = (req, res, next) => req.headers.token ? next() : res.status(401).send("Login required");
app.get("/private", log, auth, (req, res) => res.send("secret data"));

// Array of handlers
app.get("/multi", [log, auth], (req, res) => res.send("ok"));

// Async handler (Express 5 forwards rejected promises to the error handler automatically)
app.get("/users", async (req, res) => {
  const users = await User.find();
  res.json(users);
});

// Express 4: wrap async code in try/catch and call next(err)
app.get("/users4", async (req, res, next) => {
  try { res.json(await User.find()); }
  catch (err) { next(err); }
});

// Error-handling middleware: FOUR parameters
app.use((err, req, res, next) => {
  res.status(err.status || 500).json({ message: err.message });
});
Parameter Purpose
req Incoming request (params, query, body, headers)
res Outgoing response (send, json, status)
next Pass control to the next handler; next(err) triggers the error handler
err (only in error handlers) The error being handled
Key Concept: Every handler must end the request-response cycle (respond) or hand over with next(). Doing neither leaves the client hanging.
Exam Trap: An error handler is recognised only by having exactly 4 parameters, even if you do not use next. return res.send(...) prevents code below from running (avoids double responses). In Express 4, async errors without try/catch crash the app or hang the request.

Exam Trap:
  • res.send(), res.json(), res.redirect(), res.end() end the response; sending twice throws "Cannot set headers after they are sent".
  • res.status(404) alone does not send anything; you must chain .send()/.json().
  • req.body is undefined unless a body parser is registered before the route.
  • All values in params and query are strings.
  • res.json() vs res.send(obj): both give JSON for objects, but json() is explicit and also converts null/undefined correctly.

12. HTTP Methods: get, post, put, delete

Core Concept

Express provides app.METHOD(path, handler) for every HTTP verb. The four core verbs map to CRUD operations in a REST API.

Method CRUD Typical route Body? Success code Idempotent? Safe?
app.get Read /users, /users/:id No 200 Yes Yes
app.post Create /users Yes 201 No No
app.put Replace / update /users/:id Yes (full) 200 Yes No
app.patch Partial update /users/:id Yes (partial) 200 Usually No
app.delete Delete /users/:id Rarely 200 / 204 Yes No

Complete CRUD REST API (in-memory)

const express = require("express");
const app = express();
app.use(express.json());                       // needed for POST / PUT bodies

let users = [{ id: 1, name: "Asha" }, { id: 2, name: "Ravi" }];
let nextId = 3;

// READ all (supports ?name= filter)
app.get("/api/users", (req, res) => {
  const { name } = req.query;
  res.json(name ? users.filter(u => u.name.includes(name)) : users);
});

// READ one
app.get("/api/users/:id", (req, res) => {
  const user = users.find(u => u.id === Number(req.params.id));
  if (!user) return res.status(404).json({ error: "User not found" });
  res.json(user);
});

// CREATE
app.post("/api/users", (req, res) => {
  const { name } = req.body;
  if (!name) return res.status(400).json({ error: "name is required" });
  const user = { id: nextId++, name };
  users.push(user);
  res.status(201).json(user);                  // 201 Created
});

// UPDATE (replace)
app.put("/api/users/:id", (req, res) => {
  const i = users.findIndex(u => u.id === Number(req.params.id));
  if (i === -1) return res.status(404).json({ error: "User not found" });
  users[i] = { id: users[i].id, name: req.body.name };
  res.json(users[i]);
});

// DELETE
app.delete("/api/users/:id", (req, res) => {
  const before = users.length;
  users = users.filter(u => u.id !== Number(req.params.id));
  if (users.length === before) return res.status(404).json({ error: "User not found" });
  res.sendStatus(204);                         // 204 No Content
});

app.listen(3000);

Testing with curl / fetch

curl http://localhost:3000/api/users
curl -X POST   -H "Content-Type: application/json" -d '{"name":"Meera"}' http://localhost:3000/api/users
curl -X PUT    -H "Content-Type: application/json" -d '{"name":"Neha"}'  http://localhost:3000/api/users/1
curl -X DELETE http://localhost:3000/api/users/2

// Browser (React) side
fetch("/api/users", { method: "POST", headers: {"Content-Type":"application/json"}, body: JSON.stringify({ name: "Meera" }) });
 CRUD      HTTP       URL                 Mongoose equivalent
 Create    POST       /api/users          User.create(body)
 Read      GET        /api/users[/:id]    User.find() / findById(id)
 Update    PUT/PATCH  /api/users/:id      User.findByIdAndUpdate(id, body)
 Delete    DELETE     /api/users/:id      User.findByIdAndDelete(id)
Exam Trap: Browsers can send only GET/POST from plain HTML forms; PUT/DELETE need fetch/axios (or method-override). PUT replaces the whole resource (idempotent: same call repeated = same result); POST is not idempotent (repeating creates duplicates). PATCH changes only some fields. GET must never modify data. Without express.json(), req.body is undefined. app.all() handles every method; app.use() is not the same as app.all() (prefix match vs exact path).

13. Packages and Middleware

Core Concept: Middleware

Middleware is a function with access to req, res and next that executes during the request–response cycle. It can: run code, modify req/res, end the cycle, or call next() to continue. 

 Request ─► [logger] ─► [cors] ─► [express.json] ─► [auth] ─► [route] ─► Response
              next()      next()       next()          next()
                                                          │ error
                                                          ▼
                                                 [error-handling middleware]

Types of Middleware

Type Registered with Example
Application-level app.use(), app.METHOD() Logger for all routes

Writing Custom Middleware

// 1. Logger
const logger = (req, res, next) => {
  console.log(`${new Date().toISOString()} ${req.method} ${req.originalUrl}`);
  next();                                   // MUST call next (or respond)
};
app.use(logger);

// 2. Authentication (can stop the chain)
const auth = (req, res, next) => {
  const token = req.headers.authorization?.split(" ")[1];
  if (!token) return res.status(401).json({ error: "No token" });
  req.user = { id: 1 };                     // attach data for later handlers
  next();
};
app.get("/profile", auth, (req, res) => res.json(req.user));
app.use("/admin", auth);                    // only for /admin/*

// 3. Middleware factory (configurable)
const requireRole = (role) => (req, res, next) =>
  req.user?.role === role ? next() : res.status(403).json({ error: "Forbidden" });
app.delete("/api/users/:id", auth, requireRole("admin"), (req, res) => res.sendStatus(204));

// 4. Timing, response modification
app.use((req, res, next) => {
  const start = Date.now();
  res.on("finish", () => console.log(`took ${Date.now() - start}ms`));
  next();
});

// 5. 404 + error handlers (always LAST)
app.use((req, res) => res.status(404).json({ error: "Not found" }));
app.use((err, req, res, next) => res.status(500).json({ error: err.message }));

Key Concept: Middleware executes in the order of registration. A typical safe order: security (helmet) → CORS → logging → body parsers → routes → 404 → error handler.
Exam Trap: Forgetting next() hangs the request. Calling next() after sending a response runs later handlers and causes "headers already sent". Register body parsers before routes that read req.body. Error middleware must be registered last and needs 4 params. app.use(fn) without a path applies to all routes and methods. Remember: dependencies for runtime packages, devDependencies for nodemon.

14. Body-parser

Core Concept

By default Express does not read the request body; req.body is undefined. A body parser middleware reads the incoming data stream, parses it according to Content-Type, and attaches the result to req.body.

Body Formats and Parsers

Content-Type Sent by Parser
application/json fetch/axios/Postman JSON express.json()
application/x-www-form-urlencoded Classic HTML forms express.urlencoded({ extended: true })
text/plain Raw text express.text()
Binary / octet-stream Raw data express.raw()
multipart/form-data File uploads Not handled by body-parser; use multer

Using the built-in parsers (recommended)

const express = require("express");
const app = express();

app.use(express.json({ limit: "10kb" }));                  // JSON → req.body (size limit)
app.use(express.urlencoded({ extended: true }));           // form data → req.body

app.post("/signup", (req, res) => {
  const { email, password } = req.body;                    // destructure
  res.status(201).json({ received: email });
});
// JSON request:  {"email":"a@x.com","password":"123"}
// Form request:  email=a%40x.com&password=123

Using the standalone body-parser package

// npm install body-parser
const bodyParser = require("body-parser");
app.use(bodyParser.json());
app.use(bodyParser.urlencoded({ extended: true }));
// Since Express 4.16 these are the same functions as express.json / express.urlencoded

Parser for one route only

app.post("/webhook", express.raw({ type: "application/json" }), (req, res) => {
  // req.body is a Buffer (needed for signature verification)
  res.sendStatus(200);
});
extended: false extended: true
Uses Node querystring library Uses qs library
Flat key-value pairs only Supports nested objects/arrays (user[name]=A → {user:{name:"A"}}) 
 Raw HTTP body (text stream)  ──► body parser (checks Content-Type) ──► req.body (JS object)
 '{"name":"Asha"}'  ───────────────── express.json() ──────────────►  { name: "Asha" }
Exam Trap: req.body being undefined is almost always a missing express.json(), wrong order (parser after the route), or a missing Content-Type: application/json header on the request. The standalone body-parser is no longer needed for basic use since Express 4.16; but the exam may still ask for it. Neither parser handles file uploads (use multer). In Express 5, req.body is undefined (not {}) when no parser ran. Invalid JSON triggers a 400 error handled by your error middleware. Always set a limit to avoid huge-payload abuse.

15. CORS and Credentials

Core Concept

CORS (Cross-Origin Resource Sharing) is a browser-enforced security mechanism that controls whether a web page from one origin may read responses from a different origin. An origin = protocol + domain + port. The Same-Origin Policy blocks cross-origin reads by default; the server relaxes it with CORS response headers.

Page origin Request to Same origin?
http://localhost:5173 http://localhost:5173/api Yes
http://localhost:5173 (React) http://localhost:5000/api (Express) No (different port) → needs CORS
https://app.com http://app.com No (protocol)
https://app.com https://api.app.com No (subdomain)

Key CORS Headers

Header Purpose
Access-Control-Allow-Origin Which origin is allowed (* or a specific origin)
Access-Control-Allow-Methods Allowed HTTP methods
Access-Control-Allow-Headers Allowed request headers (e.g., Authorization)
Access-Control-Allow-Credentials true to allow cookies/auth
Access-Control-Max-Age How long the preflight result is cached

Preflight Request

For "non-simple" requests (methods like PUT/DELETE, JSON content-type, custom headers like Authorization) the browser first sends an automatic OPTIONS request to ask permission. Only if the server's reply allows it does the real request go out. 

 Browser (http://localhost:5173)                      Express (http://localhost:5000)
   │  OPTIONS /api/users                                 │
   │  Origin: http://localhost:5173                      │
   │  Access-Control-Request-Method: PUT                 │
   │ ──────────────────────────────────────────────────► │  PREFLIGHT
   │  204  Access-Control-Allow-Origin: http://localhost:5173
   │       Access-Control-Allow-Methods: GET,POST,PUT,DELETE
   │ ◄────────────────────────────────────────────────── │
   │  PUT /api/users/1  (actual request)                 │
   │ ──────────────────────────────────────────────────► │
   │  200 + Access-Control-Allow-Origin ...              │
   │ ◄────────────────────────────────────────────────── │

Using the cors package

// npm install cors
const cors = require("cors");

// 1. Allow every origin (fine for public APIs / quick dev)
app.use(cors());                        // Access-Control-Allow-Origin: *

// 2. Allow one specific origin
app.use(cors({ origin: "http://localhost:5173" }));

// 3. Production-grade: whitelist + credentials + methods
const whitelist = ["http://localhost:5173", "https://myapp.com"];
app.use(cors({
  origin: (origin, callback) => {
    if (!origin || whitelist.includes(origin)) callback(null, true);   // !origin = Postman/curl/server
    else callback(new Error("Not allowed by CORS"));
  },
  methods: ["GET", "POST", "PUT", "PATCH", "DELETE"],
  allowedHeaders: ["Content-Type", "Authorization"],
  credentials: true,                    // allow cookies / auth headers
  maxAge: 86400
}));

// CORS for a single route only
app.get("/public-data", cors(), (req, res) => res.json({ ok: true }));

// Manual (without package)
app.use((req, res, next) => {
  res.header("Access-Control-Allow-Origin", "http://localhost:5173");
  res.header("Access-Control-Allow-Methods", "GET,POST,PUT,DELETE,OPTIONS");
  res.header("Access-Control-Allow-Headers", "Content-Type, Authorization");
  if (req.method === "OPTIONS") return res.sendStatus(204);      // answer preflight
  next();
});

Credentials (cookies, authorization, client certificates)

By default browsers do not send or accept cookies on cross-origin requests. To allow them, both sides must opt in. 

// ---- SERVER (Express)
const cookieParser = require("cookie-parser");
app.use(cors({ origin: "http://localhost:5173", credentials: true }));   // exact origin, NOT "*"
app.use(cookieParser());

app.post("/login", (req, res) => {
  res.cookie("token", "jwt-value", {
    httpOnly: true,            // JS cannot read it (mitigates XSS)
    secure: true,              // HTTPS only (use true in production)
    sameSite: "none",          // needed for cross-site cookies (requires secure:true)
    maxAge: 24 * 60 * 60 * 1000
  });
  res.json({ message: "Logged in" });
});
app.get("/me", (req, res) => res.json({ token: req.cookies.token }));

// ---- CLIENT: fetch
fetch("http://localhost:5000/login", {
  method: "POST",
  credentials: "include",               // send/receive cookies cross-origin
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ email: "a@x.com", password: "123" })
});

// ---- CLIENT: axios
axios.post("http://localhost:5000/login", data, { withCredentials: true });
// or globally:  axios.defaults.withCredentials = true;
Client Option
fetch credentials: "include" (or "same-origin" default, "omit")
axios withCredentials: true
Server Access-Control-Allow-Credentials: true (credentials: true in cors)

Common Error and Fix

Access to fetch at 'http://localhost:5000/api' from origin 'http://localhost:5173'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present.
→ Fix: add app.use(cors({ origin: "http://localhost:5173" })) BEFORE the routes.

"...The value of the 'Access-Control-Allow-Origin' header must not be the wildcard '*'
 when the request's credentials mode is 'include'."
→ Fix: set a specific origin, not "*", when credentials: true.

Dev alternative: use the Vite/CRA proxy so the browser sees the same origin (server.proxy: { "/api": "http://localhost:5000" }) and no CORS is needed.

Key Concept: CORS is enforced by the browser, configured by the server. Postman, curl and server-to-server calls ignore CORS entirely.
Exam Trap:
  • CORS does not protect your server from requests; it only controls whether the browser lets JavaScript read the response. Attackers can still call the API directly.
  • With credentials: true the origin cannot be *, and the client must also send credentials: "include"/withCredentials: true.
  • Place app.use(cors()) before your routes; otherwise headers are missing.
  • The preflight is an OPTIONS request; the cors package answers it automatically.
  • CORS errors can also appear when the server crashes or returns an error without CORS headers, so check server logs first.
  • Cross-site cookies need SameSite=None; Secure; localhost ports count as same site but different origin.

Unit IV: High-Yield Revision Checklist

  • Express: minimal Node.js web framework; wraps http; routing + middleware; install with npm install express.
  • Server: const app = express(); app.listen(PORT, cb); read process.env.PORT.
  • Serving browsers: express.static, res.sendFile (absolute path), res.render, SPA fallback after API routes.
  • Router: express.Router(), mounted with app.use(prefix, router), paths relative to the mount point, module.exports = router.
  • Matching: in order of definition, first match wins; use = prefix, any method; get = exact path + GET.
  • Route params: :id → req.params (always strings); query → req.query; body → req.body.
  • Handler: (req, res, next); respond or next(); error handler has 4 params.
  • req / res: know the main properties and the response methods (send, json, status, redirect, sendFile, cookie).
  • Methods: GET read, POST create (201), PUT replace, PATCH partial, DELETE remove (204); idempotency.
  • Middleware: app-level, router-level, built-in, third-party, error-handling; order matters; always call next().
  • Body-parser: express.json(), express.urlencoded(); multer for files; req.body undefined without parser.
  • CORS: origin = protocol + domain + port; preflight OPTIONS; cors() package; credentials need credentials: true + specific origin + client include/withCredentials.
