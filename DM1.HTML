1. Fundamentals of Data Mining

Core Concept

Data Mining is the process of discovering interesting, previously unknown and useful patterns from large amounts of data stored in databases, data warehouses or other repositories. It is also called Knowledge Discovery from Data (KDD), though strictly mining is one step of KDD.

KDD Process (Steps)

 Raw Data (DBs, files, web)
    | 1. Data Cleaning        (remove noise, inconsistency)
    | 2. Data Integration     (combine multiple sources)
    v
 Data Warehouse / Target data
    | 3. Data Selection       (pick relevant data)
    | 4. Data Transformation  (normalize, aggregate)
    v
 Prepared Data
    | 5. DATA MINING          (apply algorithms to find patterns)
    | 6. Pattern Evaluation   (find truly interesting patterns)
    | 7. Knowledge Presentation (visualization, reports)
    v
 KNOWLEDGE
Exam Trap: Data mining is not the whole KDD process; it is only step 5 (the core step). Steps 1-4 are pre-processing.

Kinds of Data that can be Mined

  • Relational databases (tables, rows, attributes).
  • Data warehouses (multidimensional, historical, integrated).
  • Transactional databases (e.g. market-basket records).
  • Advanced: spatial, time-series, text, multimedia, web (covered in Unit VI).

2. Data Mining Functionalities

Functionalities specify the kinds of patterns to be found. Two broad groups: Descriptive (characterize general properties of data) and Predictive (use current data to predict).

Functionality Meaning Example
Concept/Class description Characterization (summarize a class) and Discrimination (compare classes) Profile of customers who buy laptops vs. phones
Association analysis Finds items that occur together (rules with support and confidence) bread → butter [support 5%, confidence 70%]
Classification Builds a model from labeled data to assign classes Loan applicant: safe / risky
Prediction Predicts a missing or future numeric value Next month's sales
Clustering Groups similar objects with no predefined labels Customer segmentation
Outlier analysis Finds objects that do not fit the general behaviour Credit card fraud
Evolution analysis Models trends in data that changes over time Stock price trends
Key Concept: Classification = supervised (class labels known). Clustering = unsupervised (labels unknown, groups discovered).

Interestingness of a pattern: easily understood, valid on new data with some certainty, potentially useful, and novel. Measures: support (how often the pattern occurs) and confidence (how often it is true).

3. Classification of Data Mining Systems

Classified by Categories
Kind of database mined Relational, transactional, object-oriented, spatial, time-series, text, multimedia, web
Kind of knowledge mined Characterization, association, classification, clustering, outlier, etc.
Kind of techniques used Machine learning, statistics, neural networks, visualization, database/warehouse-oriented; also by level of user interaction (autonomous, interactive, query-driven)
Application domain Finance, telecom, retail, bioinformatics, etc.

4. Major Issues in Data Mining

Group Issues
Mining methodology Mining different kinds of knowledge, interactive mining at multiple levels of abstraction, incorporating background knowledge, handling noisy/incomplete data, evaluating pattern interestingness
Performance Efficiency and scalability of algorithms, parallel/distributed/incremental mining for huge datasets
Data-type diversity Handling relational and complex data (text, spatial, multimedia), mining from heterogeneous and global (web) sources
User interaction Data mining query languages, presentation and visualization of results
Social Privacy, security and misuse of mined information

5. Data Pre-processing: Need

Real-world data is dirty. Poor data gives poor mining results ("garbage in, garbage out").

  • Incomplete: missing attribute values.
  • Noisy: errors or outliers (e.g. salary = -10).
  • Inconsistent: discrepancies in codes or names (e.g. age=42, birthday=03/07/2010).

6. Data Cleaning

Missing Values

  • Ignore the tuple (poor if many values missing).
  • Fill manually (slow, not scalable).
  • Fill with a global constant (e.g. "Unknown").
  • Fill with attribute mean/median, or the class-wise mean.
  • Fill with the most probable value (regression, decision tree, Bayesian inference).

Noisy Data

Technique How it works
Binning Sort the data, partition into bins, smooth by bin means, bin medians or bin boundaries
Regression Fit data to a function; the fitted line smooths out noise
Clustering Values falling outside clusters are outliers
Human + computer inspection Machine flags suspicious values, human verifies

Solved Example: Smoothing by Binning

Data (sorted): 4, 8, 15, 21, 21, 24, 25, 28, 34, equal-frequency bins of size 3.

Bin Values By means By boundaries
1 4, 8, 15 9, 9, 9 4, 4, 15
2 21, 21, 24 22, 22, 22 21, 21, 24
3 25, 28, 34 29, 29, 29 25, 25, 34
Exam Trap: In boundary smoothing each value moves to the closest of the bin's min or max. (8 is closer to 4 than 15; 28 is closer to 25 than 34.)

7. Data Integration and Transformation

7.1 Data Integration

Combining data from multiple sources into a coherent store. Issues:

  • Entity identification: same real-world entity, different names (cust_id vs customer_no).
  • Redundancy: an attribute derivable from another; detected by correlation analysis (χ² test for nominal data, correlation coefficient for numeric).
  • Data value conflicts: different units or scales (metric vs British).

Correlation coefficient: r = Σ(a−Ā)(b−B̄) / (n·σA·σB). If r > 0 positively correlated; r = 0 independent; r < 0 negatively correlated.

7.2 Data Transformation

Method Meaning
Smoothing Remove noise (binning, regression, clustering)
Aggregation Summarize, e.g. daily sales → monthly sales
Generalization Replace low-level data by higher-level concepts (street → city)
Normalization Scale values into a small range
Attribute construction Build new attributes from existing ones (area = width × height)

Normalization Formulas

Type Formula
Min-max v' = (v − min) / (max − min) × (new_max − new_min) + new_min
Z-score v' = (v − mean) / std_dev
Decimal scaling v' = v / 10j (smallest j such that max|v'| < 1)

Example: income range 12,000 to 98,000 mapped to [0,1]; v = 73,600 → (73,600−12,000)/(98,000−12,000) = 61,600/86,000 ≈ 0.716.

8. Data Reduction

Obtain a smaller representation of the data that gives (almost) the same analytical results.

Strategy Idea
Data cube aggregation Aggregate data into cube cells (quarterly sales instead of daily)
Attribute subset selection Remove irrelevant or redundant attributes (forward selection, backward elimination, decision-tree induction)
Dimensionality reduction Encode data compactly: Wavelet transform, PCA (Principal Component Analysis)
Numerosity reduction Replace data by smaller models: regression, histograms, clustering, sampling
Data compression Lossless (original fully recoverable) or lossy (approximation only)
  • Sampling types: SRSWOR (without replacement), SRSWR (with replacement), cluster sample, stratified sample.
  • Histogram: equal-width (same range per bucket) or equal-frequency (same count per bucket).
Key Concept: Reduction in volume (numerosity, cube aggregation) vs. reduction in dimensions (attribute selection, PCA). Don't mix the two.

9. Discretization and Concept Hierarchy Generation

Core Concept

Discretization divides the range of a continuous attribute into intervals, replacing raw values with interval labels (0-10, 11-20...). A concept hierarchy replaces low-level values with higher-level concepts (age → young / middle-aged / senior).

Technique Notes
Binning Top-down, unsupervised (equal-width / equal-frequency)
Histogram analysis Top-down, unsupervised
Cluster analysis Clusters become intervals; top-down or bottom-up
Entropy-based Supervised, uses class labels, picks split with minimum entropy
Interval merging by χ² analysis Bottom-up, merges adjacent similar intervals
Segmentation by natural partitioning 3-4-5 rule creates easy-to-read intervals

Concept Hierarchy for Categorical Data

 country            (most general)
    |
  state / province
    |
   city
    |
  street            (most specific)

Generated by: explicit specification by user/expert, specifying a partial ordering of attributes, specifying only a set of attributes (system orders by number of distinct values: fewer distinct values = higher level), or data clustering.

Exam Trap: In automatic hierarchy generation the attribute with the most distinct values goes at the lowest level (e.g. street), the one with the fewest at the top (country).
