1. Introduction to C#

Core Concept

C# (C-Sharp) is a modern, object-oriented, type-safe language developed by Microsoft for the .NET platform. It is readable like high-level languages, structured like the C/C++ family, and managed by the CLR. C# code compiles to IL and runs under the CLR with automatic memory management.

Used for: desktop apps, web apps, APIs, cloud services, games (Unity), enterprise software.

2. Characteristics of C#

Feature Explanation
Object-oriented Classes, objects, inheritance, polymorphism, encapsulation, abstraction
Type-safe Strict type rules reduce runtime errors
Managed language Runs under the CLR; automatic Garbage Collection
Rich standard library BCL for I/O, collections, networking, UI
Component-oriented Properties, events, delegates, attributes
Modern features Generics, LINQ, async/await, lambdas, pattern matching
Interoperability Can use COM components and native code
Security and reliability CLR verification and exception handling

3. C# vs C++ vs Java

C# vs C++

Feature C# C++
Execution Managed (CLR) Native machine code
Memory Automatic GC Manual (new/delete) + RAII
Pointers Limited (unsafe mode only) Full pointer support
Multiple inheritance Not for classes (interfaces allowed) Supported
Header files No Yes (.h)
Runtime safety Higher (type safety, bounds checks) Lower (memory corruption possible)

C# vs Java

Feature C# Java
Runtime CLR (.NET) JVM
Ecosystem ASP.NET, WPF, WinForms, Unity Spring, JavaFX, Android
Properties and events Built-in (properties, events, delegates) No direct equivalent (get/set methods)
Operator overloading Yes (limited) No
Value types Has struct Mostly reference types
Key Concept: C# is safer and faster to develop for .NET; C++ gives low-level control and maximum performance. C# and Java are syntactically similar, but C# integrates properties, events, delegates and LINQ more deeply.

4.1 Main() Method Specification

Main() is the entry point of a console application. Valid signatures: 

static void Main()
static void Main(string[] args)
static int  Main()
static int  Main(string[] args)
  • string[] args: command-line arguments. Running MyApp.exe input.txt gives args[0] = "input.txt".
  • Return type: void returns no exit code; int returns one (0 = success, non-zero = error).
Exam Trap: Main must be spelled with a capital M and must be static. It is the entry point, not a keyword.

5. Variables: Implicit and Explicit

5.1 Explicitly typed

int age = 25;
double marks = 89.5;
string name = "Deepak";

5.2 Implicitly typed (var)

var x = 10;       // inferred as int
var y = 12.5;     // inferred as double
var s = "Hello";  // inferred as string
  • var is still strongly typed; type is fixed at compile time.
  • Must be initialized at declaration (var a; is an error).
  • Type cannot change later (n = 10; n = "Ten"; is an error).
Exam Trap: var does not mean "loosely typed" like JavaScript. It is decided by the compiler, not at runtime.

6. Data Types in C#

6.1 Value types

Stored by value, generally faster, cannot be null (unless nullable). Categories: integral (byte, short, int, long), floating (float, double, decimal), char, bool, struct, enum.

6.2 Reference types

Stored as a reference, can be null: string, object, arrays, classes, interfaces, delegates. 

int a = 5;  bool ok = true;            // value types
string city = "Bareilly";
int[] arr = {1, 2, 3};                 // reference types
Type Category Size Example
int Value 4 bytes 10
double Value 8 bytes 10.5
decimal Value 16 bytes money values
char Value 2 bytes 'A'
bool Value 1 byte true
string Reference varies "Hi"
object Reference varies any type
Exam Trap: char is 2 bytes in C# (Unicode), unlike 1 byte in C/C++. string is a reference type even though it behaves like a value.

7. Boxing and Unboxing

Core Concept

Boxing converts a value type into an object (reference type) by wrapping it on the heap. Unboxing extracts the value back and needs an explicit cast plus a type check. 

      STACK                                  HEAP
 +----------------+      Boxing         +----------------+
 | int num = 10   | ------------------> | Boxed object   |
 +----------------+  (copy value)       |     [ 10 ]     |
 | object obj     | ------------------> +----------------+
 | (reference)    |   points to
 +----------------+
        ^        Unboxing: int n = (int)obj;
        '------- explicit cast copies value back to stack

int num = 10;
object obj = num;      // Boxing: num copied to heap, obj points to it

object o = 10;
int n = (int)o;        // Unboxing: explicit cast required

object bad = "10";
int m = (int)bad;      // InvalidCastException: object does not hold an int
Best practice: Avoid needless boxing. Use generics (List<int>) instead of non-generic ArrayList.

Hidden cost of boxing in a loop

ArrayList list = new ArrayList();
for (int i = 0; i < 100000; i++)
    list.Add(i);              // each i is BOXED: 100,000 heap allocations

long sum = 0;
foreach (object o in list)
    sum += (int)o;            // each item UNBOXED with a type check

// Generic version: no boxing, no unboxing
List<int> fast = new List<int>();
for (int i = 0; i < 100000; i++) fast.Add(i);

8. Solved Problems

Problem 1: Predict the output (var inference)

var a = 10;
var b = 3;
Console.WriteLine(a / b);     // Line 1
var c = 10.0;
Console.WriteLine(c / b);     // Line 2
var d = "5";
// Console.WriteLine(d + b);  // Line 3
// a = "ten";                 // Line 4
Line Result Why
1 3 Both are int: integer division truncates
2 3.3333333333333335 c is double; b is promoted
3 "53" d is a string, so + concatenates
4 Compile-time error a is permanently int

Problem 2: Trace the boxing memory journey

int score = 95;                // Step A
object boxedScore = score;     // Step B
score = 100;                   // Step C
int copy = (int)boxedScore;    // Step D
Console.WriteLine(copy);       // Step E  -> 95
  • A: score = 95 lives on the stack.
  • B: boxing allocates a heap object holding a copy of 95; boxedScore references it.
  • C: only the stack variable changes to 100; the heap copy stays 95.
  • D: unboxing copies 95 into copy.
  • E: prints 95, not 100.
Exam Trap: A boxed value is a snapshot copy. Changing the original afterwards does not change the boxed object.
