1. Class Basics

A class is a blueprint for objects. It groups data (fields) and behaviour (methods/properties) and supports encapsulation and abstraction. An object is an instance of a class. 

class Student
{
    // fields, properties, constructors, methods
}
Student s = new Student();   // object creation

2. Access Modifiers

Modifier Accessible from
public Anywhere (same and other projects)
private Only inside the same class (default for members)
protected Same class and derived classes
internal Anywhere within the same assembly/project
protected internal Same assembly OR derived classes (even in other assemblies)
private protected Same class or derived classes, but only within the same assembly
Exam Trap: Class members default to private; top-level classes default to internal. protected internal is OR, private protected is AND.

3. Fields

A field is a variable declared in a class that stores object state.

Kind Meaning
Instance field Unique per object
Static field Shared by all objects
readonly field Set once (declaration or constructor)
const field Compile-time constant 
class Employee
{
    private int id;                       // instance
    private static int count;             // static (shared)
    public readonly string Company;       // readonly
    public const int MaxAge = 60;         // const

    public Employee(string company)
    {
        Company = company;                // allowed in constructor
        count++;
    }
}

4. Properties (get / set)

A property gives controlled access to a private field, supporting encapsulation: validation, read-only/write-only access, and changing internals without breaking callers. 

private int age;
public int Age                       // read-write
{
    get { return age; }
    set { age = value; }             // 'value' is the assigned value
}

private int roll;
public int Roll { get { return roll; } }          // read-only

private string password;
public string Password { set { password = value; } }   // write-only (rare)

public string Name { get; set; }     // auto-implemented property
Key Concept: value is the implicit parameter of the set accessor. Auto-properties let the compiler create the hidden backing field.

5. Constructors

A constructor runs automatically when an object is created. Rules: same name as the class, no return type (not even void), and it can be overloaded. 

class Demo { public Demo() { Console.WriteLine("Default"); } }       // default

class Student
{
    public string Name;
    public Student(string name) { Name = name; }                     // parameterized
}

class Box
{
    int w, h;
    public Box() { w = 1; h = 1; }                                   // overloading
    public Box(int w, int h) { this.w = w; this.h = h; }
}

class Point
{
    public int X, Y;
    public Point(Point p) { X = p.X; Y = p.Y; }                      // copy (manual)
}

class Test
{
    public static int Count;
    static Test() { Count = 100; }       // static: once per class, no modifier/params
}

class Single { private Single() { } }    // private (e.g. Singleton)
Exam Trap: C# has no built-in copy constructor; write one manually. A static constructor cannot take parameters or access modifiers, and runs only once.

7. this Keyword

this refers to the current object.

class Student
{
    int id;
    public Student(int id) { this.id = id; }     // field = parameter
}

class Demo
{
    int x, y;
    public Demo() : this(1, 2) { }                // constructor chaining
    public Demo(int x, int y) { this.x = x; this.y = y; }
}

8. readonly and const

Feature const readonly
Evaluated Compile time Run time
Assigned Only at declaration Declaration or constructor
Allowed types Primitives + string Any type
Memory Inlined by compiler Stored like a normal field 
public const double PI = 3.14159;
public readonly string CollegeName;
public Student(string college) { CollegeName = college; }   // once
Exam Trap: const is implicitly static; readonly is per-instance unless declared static readonly.

9. Inheritance

A derived (child) class acquires members of a base (parent) class: code reuse and hierarchy. Syntax: class Child : Parent. 

class Person
{
    public string Name { get; set; }
    public void ShowName() => Console.WriteLine("Name: " + Name);
}
class Student : Person
{
    public int Roll { get; set; }
    public void ShowRoll() => Console.WriteLine("Roll: " + Roll);
}
Student s = new Student { Name = "Amit", Roll = 101 };
s.ShowName();  s.ShowRoll();      // Name: Amit   Roll: 101
 Single          Multilevel        Hierarchical
   A (Person)       A                 A (Animal)
   |                |                 / \
   B : A            B : A           B   C
   (Student)        |             (Dog) (Cat)
                    C : B

// Multilevel
class A { public void M1() => Console.WriteLine("A"); }
class B : A { public void M2() => Console.WriteLine("B"); }
class C : B { public void M3() => Console.WriteLine("C"); }

// Hierarchical
class Animal { public void Eat() => Console.WriteLine("Eating"); }
class Dog : Animal { public void Bark() => Console.WriteLine("Bark"); }
class Cat : Animal { public void Meow() => Console.WriteLine("Meow"); }
Exam Trap: C# does not support multiple inheritance of classes (avoids ambiguity). Achieve it with interfaces.

10. Method Overloading vs Method Overriding

Overloading (compile-time polymorphism)

Same method name, same class, different parameter lists (count, type or order). Changing only the return type is not valid. 

class Calc
{
    public int Add(int a, int b) => a + b;
    public int Add(int a, int b, int c) => a + b + c;       // different count
    public double Add(double a, double b) => a + b;         // different type
    public int Add(int a, double b) => a + (int)b;          // different order/type
}

Overriding (run-time polymorphism)

A derived class redefines a base method. The base method must be virtual, abstract or already override; the derived one uses override; the signature must match exactly. 

class Animal { public virtual void Sound() { Console.WriteLine("Animal sound"); } }
class Dog : Animal { public override void Sound() { Console.WriteLine("Dog barks"); } }

Animal a = new Dog();
a.Sound();                     // Dog barks (decided at runtime)

Sealed override

class A { public virtual void Show() => Console.WriteLine("A"); }
class B : A { public sealed override void Show() => Console.WriteLine("B"); }
// class C : B { public override void Show() { } }   // NOT allowed (sealed)
Feature Overloading Overriding
Same method name Yes Yes
Parameters Different Same
Resolved at Compile time Run time
Keywords None virtual, override
Exam Trap: Without virtual in the base class you cannot override. The declared type of the variable does not decide which override runs; the actual object does.

11. Polymorphism

Polymorphism means "one name, many forms".

  • Compile-time (static): method overloading and operator overloading.
  • Run-time (dynamic): method overriding (virtual/override) and interface dispatch.
  • Benefits: flexibility, easy extension (new derived classes without touching old code), natural real-world modelling.

12. Operator Overloading

Defines how operators (+ - * ==) behave for user-defined types. Must be public static; at least one operand must be the containing type; some come in pairs (== with !=, < with >, <= with >=). 

class Complex
{
    public int Real { get; }
    public int Imag { get; }
    public Complex(int r, int i) { Real = r; Imag = i; }

    public static Complex operator +(Complex a, Complex b)
    {
        return new Complex(a.Real + b.Real, a.Imag + b.Imag);
    }
    public override string ToString() => $"{Real} + {Imag}i";
}
Complex c3 = new Complex(2, 3) + new Complex(4, 5);
Console.WriteLine(c3);          // 6 + 8i

13. Abstract Class vs Interface

 Abstract class                          Interface
 +---------------------------+     +-----------+   +-----------+
 | abstract class Shape      |     | interface |   | interface |
 |  abstract double Area();  |     |   IA      |   |   IB      |
 |  void DisplayColor() {..} |     |  void A() |   |  void B() |
 +-------------+-------------+     +-----+-----+   +-----+-----+
               |                         \             /
 +-------------v-------------+       +----v-----------v----+
 | class Circle : Shape      |       | class Demo : IA, IB  |
 +---------------------------+       +----------------------+
 fields + constructors allowed         pure contract, multiple allowed
 single inheritance only

abstract class Shape
{
    public string Color { get; set; }
    public abstract double Area();            // no body
    public void DisplayColor() { Console.WriteLine("Color: " + Color); }   // concrete
}
class Circle : Shape
{
    public double Radius { get; set; }
    public override double Area() { return 3.14159 * Radius * Radius; }
}
Shape s = new Circle { Color = "Red", Radius = 5 };
s.DisplayColor();                    // Color: Red
Console.WriteLine(s.Area());         // 78.53975

interface IPayment { void Pay(double amount); }
class UpiPayment : IPayment
{
    public void Pay(double amount) { Console.WriteLine("Paid via UPI: " + amount); }
}

interface IA { void A(); }
interface IB { void B(); }
class Demo : IA, IB                  // multiple interface implementation
{
    public void A() => Console.WriteLine("A");
    public void B() => Console.WriteLine("B");
}
Feature Abstract class Interface
Members Abstract + concrete, fields, constructors Contract of members (traditionally no fields/constructors)
Inheritance Only one base class A class can implement many
Instantiate No No
Exam Trap: You cannot create an object of an abstract class or interface (new Shape() is an error), and a derived non-abstract class must implement every abstract member.

14. Inner / Nested Class

A class declared inside another class: groups related types, hides a helper class (private nested) and improves encapsulation. 

class Bank
{
    private string bankName = "ABC Bank";
    public void Show() { Account acc = new Account(); acc.Display(); }

    private class Account
    {
        public void Display() { Console.WriteLine("This is a bank account."); }
    }
}

15. Delegates

A delegate is a type-safe reference to a method (a safe function pointer). It can point to static or instance methods and supports multicast. Delegates are the foundation of events. 

delegate int Operation(int a, int b);
class Calc
{
    public static int Add(int x, int y) => x + y;
    public static int Sub(int x, int y) => x - y;
}
Operation op = Calc.Add;
Console.WriteLine(op(10, 5));      // 15
op = Calc.Sub;
Console.WriteLine(op(10, 5));      // 5

// Multicast
delegate void Notify();
static void Msg1() => Console.WriteLine("Msg1");
static void Msg2() => Console.WriteLine("Msg2");
Notify n = Msg1;
n += Msg2;
n();                               // Msg1, Msg2

Built-in delegate types: Action<> (no return value), Func<> (returns a value), Predicate<> (returns bool).

Exam Trap: The method signature (parameters and return type) must match the delegate's declaration exactly.

16. Partial Classes

A class split across multiple files with the partial keyword; the compiler merges them. Common in large teams and heavily used by Windows Forms designer code (Form1.Designer.cs). 

// Student1.cs
public partial class Student { public int Id { get; set; } }
// Student2.cs
public partial class Student { public string Name { get; set; } }

Student s = new Student { Id = 1, Name = "Amit" };

18. Exception Handling

Core Concept

An exception is an abnormal event at run time that stops normal flow. Handling it uses try, catch, finally and throw. 

 try { risky code }
        |
 Exception thrown?
   Yes |                 | No
       v                 v
 matching catch      catch skipped
       \                 /
        v               v
        finally { ALWAYS runs }
              |
              v
     Program continues normally

try
{
    int a = 10, b = 0;
    Console.WriteLine(a / b);
}
catch (DivideByZeroException ex)
{
    Console.WriteLine("Cannot divide by zero");
}
finally
{
    Console.WriteLine("Program finished safely");
}
// Output: Cannot divide by zero / Program finished safely

Multiple catch blocks

try { int[] a = {1, 2}; Console.WriteLine(a[5]); }
catch (IndexOutOfRangeException) { Console.WriteLine("Index out of range"); }
catch (Exception) { Console.WriteLine("General error"); }   // general LAST

Custom (user-defined) exception

class AgeException : Exception
{
    public AgeException(string msg) : base(msg) { }
}
static void CheckAge(int age)
{
    if (age < 18) throw new AgeException("Age must be 18+");
}
try { CheckAge(16); }
catch (AgeException ex) { Console.WriteLine(ex.Message); }   // Age must be 18+

Common built-in exceptions: DivideByZeroException, NullReferenceException, FormatException, IndexOutOfRangeException, FileNotFoundException.

Exam Trap: Put the specific catch before catch (Exception); the other order is a compile error. finally runs whether or not an exception occurs.

19. How the CLR Picks the Method (vtable)

For a.Sound() with Animal a, the compiler only knows the declared type, so it checks that Animal.Sound() exists. Because the method is virtual, it leaves a virtual method table (vtable) lookup in the compiled code. At run time the CLR looks at the actual object and calls its most-derived override. That is why overloading is compile-time and overriding is run-time.

20. Solved Problems

Problem 1: Which Sound() runs?

class Animal { public virtual void Sound() => Console.WriteLine("Some generic sound"); }
class Dog : Animal { public override void Sound() => Console.WriteLine("Bark"); }
class Puppy : Dog { public override void Sound() => Console.WriteLine("Yip"); }

Animal a1 = new Animal();
Animal a2 = new Dog();
Animal a3 = new Puppy();
Dog d = new Puppy();
a1.Sound(); a2.Sound(); a3.Sound(); d.Sound();
Call Output Reason
a1.Sound() Some generic sound Actual object is Animal
a2.Sound() Bark Actual object is Dog
a3.Sound() Yip Most-derived override (Puppy)
d.Sound() Yip Declared Dog, actual Puppy

Problem 2: Exception propagation

static void B()
{
    Console.WriteLine("B: before throw");
    throw new InvalidOperationException("Something broke in B");
}
static void A()
{
    Console.WriteLine("A: calling B");
    B();
    Console.WriteLine("A: after calling B");      // never reached
}
static void Main()
{
    try
    {
        Console.WriteLine("Main: calling A");
        A();
        Console.WriteLine("Main: after calling A");   // never reached
    }
    catch (InvalidOperationException ex)
    {
        Console.WriteLine("Main: caught -> " + ex.Message);
    }
    finally { Console.WriteLine("Main: finally always runs"); }
}
 Output:
 Main: calling A
 A: calling B
 B: before throw
 Main: caught -> Something broke in B
 Main: finally always runs

B has no handler, so the exception unwinds out of B, then A (skipping their remaining lines) until Main's matching catch handles it.

Problem 3: Interface + polymorphism

interface IPayment { void Pay(double amount); }
class CardPayment : IPayment { public void Pay(double amount) => Console.WriteLine($"Card payment of {amount:C}"); }
class UpiPayment  : IPayment { public void Pay(double amount) => Console.WriteLine($"UPI payment of {amount:C}"); }

List<IPayment> payments = new List<IPayment> { new CardPayment(), new UpiPayment() };
double total = 0;
foreach (IPayment p in payments) { p.Pay(250.50); total += 250.50; }
Console.WriteLine($"Total processed: {total:C}");

The list holds two different classes but treats them uniformly through IPayment; each Pay() resolves at run time to the right implementation. Total = 501.00.
