1. Introduction to JavaScript

Core Concept

JavaScript (JS) is a high-level, interpreted (JIT-compiled), dynamically typed, multi-paradigm language standardized as ECMAScript (ECMA-262). It runs in browsers (V8, SpiderMonkey) and on servers via Node.js, which is why it forms the "J" in the MERN stack.

Technical Breakdown

  • Created: 1995 by Brendan Eich at Netscape (originally "Mocha").
  • Engine pipeline: Source → Parser → AST → Interpreter (bytecode) → JIT compiler (optimized machine code).
  • Roles: client-side (DOM, UI), server-side (Node.js/Express), database scripting (MongoDB shell). 
 Source Code --> Parser --> AST --> Interpreter --> Bytecode
                                         |
                                  (hot code)
                                         v
                                   JIT Compiler --> Machine Code

Example: A single language lets one developer write React UI, Express API and MongoDB queries. 

console.log("Hello, MERN!");   // prints to console (browser or Node)
Exam Trap: JavaScript is not Java. They are unrelated languages. JS is ECMAScript-based, prototype-oriented and dynamically typed; Java is class-based and statically typed.

2. Features of JavaScript

Feature Explanation
Interpreted / JIT No separate compile step by the programmer
Dynamically typed Types are checked at runtime; a variable can change type
Single-threaded One call stack; concurrency via the event loop
Prototype-based OOP Objects inherit from other objects (ES6 class is syntactic sugar)
First-class functions Functions can be stored in variables, passed and returned
Event-driven, async Callbacks, Promises, async/await
Lightweight & cross-platform Runs on any device with an engine
Case-sensitive name and Name are different identifiers
Key Concept: "Single-threaded + non-blocking" is the foundation of Node.js performance.
Exam Trap: Single-threaded does not mean it cannot do async work. The host environment (browser/Node) performs the async tasks, and the event loop schedules the callbacks.

3. Scopes

Core Concept

Scope is the region of code where a variable is accessible. JS has global, function, block ({ }) and module scope, resolved through the lexical scope chain (inner scopes look outward, never inward). 

let g = "global";               // global scope
function demo() {
  let f = "function";           // function scope
  if (true) {
    let b = "block";            // block scope (let/const only)
    var v = "var-leaks";        // var ignores block scope
  }
  console.log(f, v);            // OK
  console.log(b);               // ReferenceError: b is not defined
}
demo();
 +-- Global ---------------------------+
 |  g                                  |
 |  +-- Function demo() -------------+  |
 |  |  f, v                          |  |
 |  |  +-- Block { } ------------+   |  |
 |  |  |  b                      |   |  |
 |  |  +-------------------------+   |  |
 |  +--------------------------------+  |
 +--------------------------------------+
 Lookup goes: Block -> Function -> Global

Closure: a function that remembers variables from its outer scope even after the outer function has returned. 

function counter() {
  let c = 0;
  return () => ++c;      // inner function "closes over" c
}
const next = counter();
next(); next();          // 1, 2
Exam Trap: Assigning to an undeclared variable (x = 5;) silently creates a global in sloppy mode. Use "use strict" to turn this into an error.

4. Variables: var, let and const

Property var let const

console.log(a);   // undefined (var hoisted)

console.log(b);   // ReferenceError (TDZ)

const user = { name: "Asha" };

Best practice: Default to const, use let when reassigning, and avoid var.

5. Data Types

Core Concept

JS has 7 primitive types (immutable, stored by value) and Object (stored by reference).

Type Example Note
Number 42, 3.14, NaN, Infinity 64-bit float (IEEE 754)
BigInt 123n Arbitrary-size integers
String "hi", 'hi', `hi` Immutable text
Boolean true, false
Undefined let x; Declared but not assigned
Null null Intentional "no value"
Symbol Symbol("id") Unique identifier
Object {}, [], function(){}, new Date() Reference type 
typeof 42;          // "number"
typeof "a";         // "string"
typeof null;        // "object"  (historic bug!)
typeof undefined;   // "undefined"
typeof [];          // "object"  -> use Array.isArray([])
typeof (() => {});  // "function"

0.1 + 0.2;          // 0.30000000000000004 (floating-point)
"5" + 2;            // "52"  (coercion to string)
"5" - 2;            // 3     (coercion to number)

let a = {n:1}, b = a; b.n = 9;  // a.n is also 9 (shared reference)

Falsy values (8): false, 0, -0, 0n, "", null, undefined, NaN. Everything else is truthy, including "0", [] and {}.

Exam Trap: typeof null === "object"; NaN !== NaN (use Number.isNaN()); typeof an array is "object".

6. Conditional Statements

Conditionals select which code runs based on a Boolean test.

// if / else if / else
let marks = 72;
if (marks >= 90) console.log("A");
else if (marks >= 60) console.log("B");
else console.log("C");

// switch (uses strict ===; needs break to prevent fall-through)
switch (new Date().getDay()) {
  case 0: console.log("Sunday"); break;
  case 6: console.log("Saturday"); break;
  default: console.log("Weekday");
}

// Ternary
const status = marks >= 40 ? "Pass" : "Fail";

// Short-circuit, nullish coalescing, optional chaining
const name = user && user.name;      // && returns first falsy or last value
const port = process.env.PORT ?? 3000; // ?? only for null/undefined
const city = user?.address?.city;      // undefined if any link is missing
Exam Trap: || treats 0 and "" as falsy, while ?? does not. switch without break falls through to the next case.

Loop Use

Exam Trap: Use for...of for arrays. for...in returns string indices and may include inherited properties.

10. Functions

Core Concept

A function is a reusable block of code that takes parameters and may return a value. In JS functions are first-class objects. 

// 1. Declaration (hoisted fully, callable before definition)
function add(a, b) { return a + b; }

// 2. Expression (not hoisted)
const sub = function (a, b) { return a - b; };

// 3. Arrow function (ES6): lexical `this`, no own `arguments`
const mul = (a, b) => a * b;

// Default, rest parameters
function greet(name = "Guest", ...tags) { return `Hi ${name} ${tags.length}`; }

// Higher-order function: takes or returns a function
const twice = (fn, x) => fn(fn(x));
twice(n => n + 3, 1);     // 7

// IIFE: runs immediately
(function () { console.log("run once"); })();

// Callback
setTimeout(() => console.log("later"), 1000);
Aspect Normal function Arrow function
this Depends on how it is called Inherited from enclosing scope
new (constructor) Yes No
arguments Yes No
Exam Trap: Function declarations are hoisted, but function expressions are not. Arrow functions should not be used as object methods or constructors. A function with no return gives undefined.

11. Anonymous Functions

An anonymous function has no name. It is typically used inline as a callback, in an IIFE, or assigned to a variable. 

setTimeout(function () { console.log("anon"); }, 500);  // anonymous callback
document.addEventListener("click", () => console.log("clicked")); // anonymous arrow
const f = function () {};      // anonymous, but f.name === "f" (inferred)
[1,2,3].map(x => x * 2);       // anonymous arrow passed as argument

Pros: concise, avoids polluting the namespace. Cons: harder to debug because stack traces are less clear. Naming functions is recommended for complex logic.

Key Concept: A function declaration must have a name, so function(){} alone as a statement is a SyntaxError.

12. Map, Filter, Reduce

These are higher-order array methods. They are declarative and do not mutate the original array (map and filter return new arrays).

Method Purpose Returns Callback signature
map Transform each element New array, same length (item, index, array)
filter Keep elements passing a test New array, shorter or equal (item, index, array)
reduce Combine all into a single value Any single value (acc, item, index, array) 
const nums = [1, 2, 3, 4, 5];

const squares = nums.map(n => n * n);         // [1,4,9,16,25]
const evens   = nums.filter(n => n % 2 === 0); // [2,4]
const sum     = nums.reduce((acc, n) => acc + n, 0); // 15

// Chaining: sum of squares of odd numbers
const result = nums
  .filter(n => n % 2)          // [1,3,5]
  .map(n => n * n)             // [1,9,25]
  .reduce((a, n) => a + n, 0); // 35

// reduce to group data
const words = ["a","bb","cc"];
const byLen = words.reduce((acc, w) => {
  (acc[w.length] ||= []).push(w);
  return acc;
}, {});   // { "1":["a"], "2":["bb","cc"] }
 reduce trace: [1,2,3], init 0
 acc=0 , n=1 -> 1
 acc=1 , n=2 -> 3
 acc=3 , n=3 -> 6   (final result)
Exam Trap: reduce on an empty array without an initial value throws a TypeError. map returns undefined for elements if you forget return in a braces body. forEach returns undefined, so it cannot be chained.

13. Event Loop

Core Concept

The Event Loop is the mechanism that lets single-threaded JavaScript perform non-blocking I/O. It continuously checks whether the Call Stack is empty and, if so, pushes pending callbacks from the queues onto it.

Components

  • Call Stack: LIFO structure that tracks the currently executing functions.
  • Web APIs / Node APIs (libuv): handle timers, HTTP, file I/O outside the stack.
  • Macrotask (Callback) Queue: setTimeout, setInterval, I/O, UI events.
  • Microtask Queue: Promise .then/.catch, async/await continuations, queueMicrotask. It has higher priority and is drained completely after each task. 
   +-------------+        +--------------------+
   | Call Stack  |<-------| Event Loop         |
   +------+------+  push  +---+-----------+----+
          | async call        ^           ^
          v                   |           |
   +-------------+     +------+----+ +----+---------+
   | Web/Node API|---> | Microtask | | Macrotask    |
   | (timers,I/O)|     | Queue     | | Queue        |
   +-------------+     +-----------+ +--------------+
   Priority: Stack -> Microtasks -> Macrotasks

console.log("1 start");
setTimeout(() => console.log("4 timeout"), 0);          // macrotask
Promise.resolve().then(() => console.log("3 promise")); // microtask
console.log("2 end");
// Output: 1 start, 2 end, 3 promise, 4 timeout

Real-world analogy: A single chef (call stack) hands slow tasks (baking) to an oven timer (Web API). When the timer rings, the order waits in a queue until the chef is free. Urgent "VIP tickets" (microtasks) are served first.

Exam Trap: setTimeout(fn, 0) does not run immediately. It runs after the current stack and all microtasks finish. A long synchronous loop blocks the entire event loop. Promises (microtasks) always run before timers (macrotasks).
