1. Data Warehouse and OLAP Technology

A data warehouse is a repository of information collected from multiple sources, stored under a unified schema, used for decision support. Four features (W. H. Inmon):

Feature Meaning
Subject-oriented Organized around subjects (customer, sales), not applications
Integrated Consistent naming, encoding, units from many sources
Time-variant Holds historical data (5-10 years); every record has a time element
Non-volatile Data is loaded and read; not updated or deleted in place

OLTP vs OLAP

Point OLTP OLAP
Purpose Day-to-day transactions Analysis, decision support
Users Clerks, DBAs Managers, analysts
Data Current, detailed Historical, summarized
Design ER model, application-oriented Star/snowflake, subject-oriented
Access Short read/write Mostly complex reads

2. Multidimensional Data Model

Data is viewed as a data cube defined by dimensions (time, item, location) and facts (measures such as dollars_sold). Each cube is a cuboid; the lattice of cuboids for n dimensions has 2n cuboids (without hierarchies). The top (apex) cuboid is the grand total; the base cuboid has all dimensions.

Schemas

 STAR                         SNOWFLAKE
 time --+                     time --+      city
 item --+-- [FACT SALES]      item --+--[FACT]--location--city
 loc  --+                     (dimension tables normalized)
 Fact constellation = several fact tables sharing dimensions
Schema Feature
Star One fact table + one denormalized table per dimension; fast, redundant
Snowflake Dimension tables normalized; less space, more joins
Fact constellation Multiple fact tables share dimension tables (galaxy schema)

OLAP Operations

Operation Effect
Roll-up Climb a hierarchy / reduce dimensions (city → country)
Drill-down Reverse of roll-up: more detail (quarter → month)
Slice Select on ONE dimension (time = Q1)
Dice Select on TWO or more dimensions (sub-cube)
Pivot (rotate) Rotate axes to give a different view
Exam Trap: Slice = one dimension; dice = two or more. Measure types: distributive (sum, count, min, max), algebraic (avg), holistic (median, rank).

3. Data Warehouse Architecture

 Tier 3: Front end   - query, reporting, OLAP and mining tools
 Tier 2: OLAP server - ROLAP / MOLAP / HOLAP
 Tier 1: Warehouse DB - Metadata + Monitor + Integrator
            ^
 ETL (Extract, Transform, Load) from operational DBs and external sources
  • Models: Enterprise warehouse (whole organization), Data mart (one department), Virtual warehouse (views over operational DBs).
  • Metadata: data about data: source schema, warehouse structure, mappings, operational and business metadata.

4. Data Warehouse Implementation

Server Idea Trade-off
ROLAP Relational DB + SQL extensions Scalable, slower queries
MOLAP Array-based multidimensional storage Fast, sparse data wastes space
HOLAP Detail in relational, aggregates in arrays Balance of both
  • Cube materialization: full (all cuboids), none, or partial (selected cuboids; most practical).
  • Indexing: bitmap index (good for low-cardinality attributes) and join index.

5. From Data Warehousing to Data Mining

Uses: information processing (queries, reports), analytical processing (OLAP), and data mining. OLAM (OLAP Mining) integrates OLAP with mining: mining on a high-quality cleaned warehouse, interactive exploration at multiple abstraction levels, and online selection of mining functions.

6. Data Mining Primitives and Query Languages

A mining task is specified by primitives: (1) task-relevant data, (2) kind of knowledge to mine, (3) background knowledge (concept hierarchies), (4) interestingness measures and thresholds, (5) presentation and visualization of results. 

use database AllElectronics_db
mine characteristics as customerPurchasing
analyze count%
in relevance to age, income, category
from customer C, item I, purchases P
with noise threshold = 0.05

DMQL (Data Mining Query Language) is SQL-like and covers data specification, mining kind (mine associations / classification / characteristics / comparison), hierarchy specification (define hierarchy), and interestingness (with support threshold).
